# atlas

## Что делает

`atlas` ведёт методологию кольца эталонного процесса и документы эталона СВТ: коды Ш/П/Ч/К/Д, два прохода, Документ 1 и Документ 2, роли и клиентские пути, стыки с логистикой.

Код СВТ 2.0, стек и скоуп справочников — [`svt-architecture`](../svt/svt-architecture.md). Синхронизация разделов 0 / 1а / 1б план-графика логистики — [`plan-grafik-md-html`](plan-grafik-md-html.md).

## Когда брать

| Ситуация | Куда |
|---|---|
| Файлы в `docs/docs/svt-v-atlas/`, идеальный процесс, кольцо, шаги Ш, точки Ч | Этот скил |
| Стык СВТ с эталоном логистики (П3, Д-14, часть П1), критика документа, вопрос «своё кольцо или механизм П3» | Этот скил |
| Заполнить «как сейчас», обработать логи, шаблон владельцу, промпт 2а, промпт 1, промпт 3 | Этот скил, пакет `etalon-to-dev/` или `shablony/` |
| Разделы 0 / 1а / 1б план-графика, MD ↔ HTML | [`plan-grafik-md-html`](plan-grafik-md-html.md) |
| SQL, грид, накат SP, скоуп справочников | трек СВТ |

## Что нужно до старта

Живой эталон для правок — `docs/docs/svt-v-atlas/SVT-idealnyy-process-2.7.html`. Карту файлов, роли и права агент читает в `docs-svt.md` скила до правки ролей или состава документов.

Образец состава разделов для правления — `logistika-etalon-pravlenie-2-1.html` в папке скила. Текст, шаги Ш, КТ, даты и светофоры логистики в документ СВТ не копируются.

Факты as-is берутся из материалов, которые дал пользователь. Нет факта — пометка `пробел`.

## Как устроено

Сначала [`SKILL.md`](../../skills/atlas/SKILL.md). Дальше — файл под задачу:

| Задача | Файл |
|---|---|
| Метод кольца, коды, два прохода, два документа | `method.md` |
| Как кольцо кладётся на СВТ | `svt.md` |
| Документация СВТ, роли, какие файлы живые | `docs-svt.md` |
| Проход «от эталона к разработке», логи, шаблон владельца | `etalon-to-dev/README.md` |
| Шаблоны с рабочего стола «АТЛАС ШАБЛОНЫ» | `shablony/README.md` |
| Образец документа для правления | `logistika-etalon-pravlenie-2-1.html` |

Файлы `.docx` и `.pdf` в `shablony/` открываются по указателю в `shablony/README.md`. Проход, который пользователь не просил, не запускается. Живой файл СВТ — HTML.

Технический обмен с фронтендом Атласа описан в `docs-svt.md`, раздел «Обмен СВТ с Атласом». В эталон как действующий обмен его вписывают после выхода на прод.

## Сработало, если

- Целевое и факт помечены: факт, есть сегодня, гипотеза или пробел.
- Правки эталона идут в `SVT-idealnyy-process-2.7.html`. Файлы из таблицы «Живые файлы» в `SKILL.md`, которые помечены «не править», не меняются.
- Шаги, даты, контрольные точки и роли логистики остаются в материалах логистики.
- Кольцо SVG `#svt-ring` меняется по явной просьбе.

## Куда встаёт

Отдельный трек от кода. [`svt-architecture`](../svt/svt-architecture.md) отвечает за стек и скоуп. [`plan-grafik-md-html`](plan-grafik-md-html.md) забирает синхронизацию трёх разделов план-графика логистики.
