# to-spec

## Что делает

`to-spec` собирает уже решённое в этом разговоре в снимок `docs/tasks/SVT-<номер>-<slug>.md`. Новых решений он не принимает. При расхождении верны код и skill: постановка не становится каноном и не заменяет [`add-reference-book`](add-reference-book.md).

## Когда брать

Человек явно просит постановку, `to-spec` или запись в `docs/tasks`. Сам агент скил не берёт. Процедура — [`SKILL.md`](../../skills/to-spec/SKILL.md).

| Ситуация | Куда |
|---|---|
| Ветки уже закрыты, нужен файл постановки | Этот скил |
| План ещё не разобран | [`grill-with-docs`](grill-with-docs.md) |
| Писать справочник | [`add-reference-book`](add-reference-book.md) |
| Унести незаконченный разговор | [`handoff`](handoff.md) |

## Что нужно до старта

Решения уже есть в этом разговоре. Номер `SVT-*` называет человек. Без номера файл не создаётся, черновик остаётся в ответе.

## Снимок

До файла каждый критерий связан с проверкой, которая может его опровергнуть. Поведение на C# входит в постановку вместе с unit-тестом, без отдельного «да». Контракт DTO, smoke грида и снимок OpenAPI называются, только если задача их меняет. Факт, который тест не видит, остаётся допущением в «Заметках» и тест не заменяет. Вопрос, меняется ли процедура или DTO, сюда не входит: такое решение либо уже есть в «Решениях», либо остаётся пробелом.

В файл попадает каждое поведение, которое уже прозвучало, и unit-тест на C#-поведение из правила разработки. Другое поведение из общей осведомлённости модели не добавляется. Текстовый результат — буквальный образец из разговора; формат, которого в разговоре не было, в файл не додумывается. Принцип из `architecture.md` не копируется: на него даётся ссылка.

## Частые вопросы

**Агент спросил, какие файлы менять.**

До файла агент называет проверки, а не спрашивает, какие файлы менять. «Да» на сам unit-тест не нужно. Скоуп кода берётся из уже сказанного в разговоре.

**Номер задачи агент придумал сам.**

Номер `SVT-*` берётся только из слов пользователя. Занятый `docs/tasks/SVT-<номер>-*.md` молча не перезаписывается.

**В backlog появилась галочка.**

Скил не ставит `[x]` и не правит канон. Строку трассировки в `backlog.md` можно предложить; пишет её после отдельного «да».

## Сработало, если

- Файл лежит в `docs/tasks/` и в первой строке сказано, что при расхождении верны код и skill.
- Есть короткие «Проблема» и «Что меняется в работе», список решений со ссылками, «Как проверяем» с проверкой на каждый критерий.
- У критерия C#-поведения в «Что сделать» и «Как проверяем» назван unit-тест. Текстовый результат дан буквальным образцом из разговора.
- Файлы канона не изменились.
