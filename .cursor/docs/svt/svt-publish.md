# svt-publish

## Что делает

`svt-publish` собирает пакет одной версии в `C:\publish\{версия}` и кладёт рядом zip этой папки. В пакете приложение (`v2`), склейка скриптов миграции или оба. На базу по умолчанию скрипт не ходит: локальный накат склейки — режим `local`, накат SoT — [`svt-create-programmability`](svt-create-programmability.md).

## Когда брать

Человек вызывает `/publish`. Агент берёт скил сам, когда просят опубликовать пакет, собрать версию или обновить `C:\publish`. Оба входа ведут в один [`SKILL.md`](../../skills/svt-publish/SKILL.md).

| Ситуация | Куда |
|---|---|
| Собрать пакет версии в `C:\publish` | Этот скил |
| Накатить SP, fn и view из SoT на локальную `mdm` | [`svt-create-programmability`](svt-create-programmability.md) |
| Написать справочник и его SQL | [`svt-migrate-catalog`](svt-migrate-catalog.md); публикация — когда SoT и папка релиза уже собраны |

## Что нужно до старта

Запуск из корня репозитория `c:\Work\BlazorSVT`. Имя папки в `Migrations/` сравнивается с `VersionPrefix` в `BlazorSvt/BlazorSvt.csproj`.

Режим `local` читает `Database:MdmDb` в `BlazorSvt/appsettings.json`. Сервер команды — `localhost`, база — `mdm`. При SQL-логине используются `User ID` и пароль, при `Trusted_Connection` — вход Windows. `appsettings.json` не менять. Нужен `sqlcmd`.

## Пакет версии

Без режима скрипт собирает приложение и склейку. `app` и `sql` оставляют в пакете только свою часть. `local` делает то же, что сборка приложения со склейкой, и выполняет файл на локальной `mdm` до подмены уже лежащего пакета. Если `VersionPrefix` и максимальная папка миграции разошлись, вместе их собрать нельзя: скрипт спрашивает, отменить запуск, опубликовать только приложение или только скрипты.

## Частые вопросы

**Пакет появился в `C:\publish\v2`.**

Пакет лежит в `C:\publish\{версия}`, zip — рядом. Каталог `C:\publish\v2` этот скил не пишет.

**Скрипт накатил базу.**

Режимы `app`, `sql` и запуск без режима базу не трогают. Накат склейки — `local`. Накат файлов SoT — [`svt-create-programmability`](svt-create-programmability.md).

**Версия приложения и последняя папка скриптов не совпали.**

В ответе три пункта: отменить, только приложение, только скрипты. Пока пункт не выбран, папка версии и zip остаются как были.

## Сработало, если

- В ответе есть `Mode`, путь `Package` и путь `Zip`.
- При несовпадении версий показан вопрос, и пакет не записан, пока не выбран пункт 2 или 3.
- При ошибке sqlcmd показан его вывод, прежние папка версии и zip на месте.
- Файлы в `SqlScripts/` и `appsettings.json` не изменились.

## Куда встаёт

Шаг после [`svt-migrate-catalog`](svt-migrate-catalog.md), когда SQL уже лежит в SoT и в папке релиза. Рядом [`svt-create-programmability`](svt-create-programmability.md) выполняет Programmability из SoT на localhost. Цепочка — [`docs/README.md`](../README.md).
