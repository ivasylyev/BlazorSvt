# svt-create-review-package

## Что делает

`svt-create-review-package` собирает zip пакета документов для архитектурного ревью и кладёт его в `docs/output-review-package.zip`. Страницы Confluence скрипт не публикует: пустая ячейка ссылки в таблице пакета значит, что страница ещё не заведена.

## Когда брать

Человек вызывает `/create_review_package`. Агент берёт скил сам, когда просят собрать пакет на ревью, пакет для архитектурного ревью или `svt-create-review-package`. Оба входа ведут в один [`SKILL.md`](../../skills/svt-create-review-package/SKILL.md).

| Ситуация | Куда |
|---|---|
| Собрать zip пакета архитектурного ревью | Этот скил |
| Ревью навыков и документов агента | [`skill-review`](../common/skill-review.md) |
| Пакет версии приложения в `C:\publish` | [`svt-publish`](svt-publish.md) |

## Что нужно до старта

Запуск из корня репозитория `c:\Work\BlazorSVT`. Без `-NoZip` и `-Destination`, пока эти флаги не названы.

## Сборка пакета

Скрипт читает таблицу в [`README`](../../../docs/output-review-package/README.md) пакета. Строка со ссылкой заменяет упоминания файла на страницу Confluence. Пустая ячейка копирует файл как есть. Строки таблицы и адреса в этот скил не переносятся. Канон содержимого остаётся в `svt-architecture` и в HTML идеального процесса.

## Частые вопросы

**Навык выложил страницы в Confluence.**

Скрипт заканчивается на zip. Кто публикует страницы, у которых ссылка уже заполнена, этот скил не задаёт.

## Сработало, если

- В ответе есть путь `docs/output-review-package.zip` и сообщение, что сгенерированные копии убраны из папки пакета.
- При ошибке скрипта показан его вывод, повторного запуска нет.
- Файлы канона `svt-architecture` не изменились, zip не закоммичен.

## Куда встаёт

Самостоятельный запуск рядом с [`svt-architecture`](svt-architecture.md): тот навык держит канон, этот собирает zip. В цепочку справочник → накат → пакет версии не входит. Цепочка — [`docs/README.md`](../README.md).
