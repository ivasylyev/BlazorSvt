# Веха 9 — MVP заявок на проде для альфа-пользователей (Шаги: Разработка, Среды, Клиентский опыт, Внедрение, Закрытие и изменения)

**Оценка:** 166.9 / 85.4 / —

Веха Атласа: да.

Заявки идут первыми, как в Атласе; тираж чтения (вехи 12–17) идёт параллельно с отставанием и старт заявок не держит. Старт держит пункт 3.1.1: бизнес утвердил роли Р-01…Р-19. Проверки этих ролей в коде появляются в 21.1.

Домен «Заявки» разложен на три вехи: MVP для альфа-пользователей (9), ОПЭ (10), ПЭ (11).

Домен «Заявки» справочников не содержит. `TransportRequest` и `MassiveRequest` вне скоупа и не переносятся. Модуль ещё не оформлен требованиями. Пункты разработки модуля — ориентир оценки; состав фиксирует аналитика первой задачи пакета. Пути, заключение и обучение стоят до релиза.

Заявка нового модуля хранится только в новом контуре, write-through нет. С релиза MVP (9.3.18) новым модулем пользуются только альфа-пользователи: проверяют работу, собирают обратную связь, по ней исправляются ошибки и дорабатывается функционал. Обработчик новых заявок на MVP — владелец системы, инициаторы — несколько наиболее лояльных пользователей легаси. Остальные пользователи до ОПЭ работают в легаси. С ОПЭ все пользователи работают только в новом контуре; старый технически включён и работает вхолостую. Возврат пользователей в старый контур — только при инциденте уровня шоу-стоппер в новом, по решению владельца продукта (Р-01). Перед ОПЭ открытые заявки дорабатывают в легаси. Старые заявки в новый модуль не переносятся. На ПЭ создание и обработку в легаси выключают, легаси остаётся просмотром истории. Остальной легаси работает как прежде. Откат не возвращает заявки нового контура в легаси.

Новую ставку по заявке заводят в легаси и связывают в модуле после синхронизации справочника ставок.
