# Реестр справочников СВТ 2.0

## Назначение

Провести ревизию справочников в СВТ 1.0, определить скоуп и приоритеты, чтобы не переносить неиспользуемый функционал в СВТ 2.0.

| Вопрос | Результат | Комментарий |
|---|---|---|
| Решить, какие справочники нужны | Выполнено | Канон — этот файл |
| Приоритет | Выполнено | Канон — этот файл |
| Структура | Выполнено | Канон — этот файл |

## Источник истины

Сырой список легаси: вложение Confluence «Все справочники СВТ 20.08.xlsx» на странице [«Справочники для переноса»](https://confluence.sibur.local/pages/viewpage.action?pageId=573822390) (pageId 573822390). Excel не хранится в репозитории и **не** является живым скоупом.

Этот файл в репозитории — источник истины (SoT) по составу, доменам, работам, меню и приоритетам. План ([roadmap.md](roadmap.md)) и чеклист ([backlog.md](backlog.md)) подгоняются под изменения здесь. Копия на Confluence — для ревью бизнеса; при расхождении канон — репозиторий.

## Как читать

| Колонка | Смысл |
|---|---|
| ID | Идентификатор справочника; ссылка на **прод** `https://s001as-svt.sibur.local/masterdata/{id}` |
| RO (только для чтения) / E (редактор) / L (загрузчик) | Необходимость работ: `[x]` или `[ ]` — да, `—` — нет. **RO** отмечен (`[x]`), если read-only уже на проде; иначе `[ ]`. **E** и **L** пока не отмечаем (работы необходимы → `[ ]`, иначе `—`) |
| Пр. RO / Пр. E / Пр. L | Приоритет внутри домена (`1` раньше `2` раньше `3`). Если работы не нужны — `-`. Для E/L, где контур есть, скопирован Пр. RO |
| Атлас | Очередь параллельного потока RO для API Атласа (коды smart-lookup): `1`…`4` — порядок переноса; `-` — не в очереди Атласа. Поток **выше** остатка домена «Ставки» и идёт отдельно от порядка доменов |
| Меню ЕО | Правило видимости **после вехи 6**: `да` — пункт виден редактору домена (сейчас эта роль называется «Единое Окно»), `нет` — только «Админ». До вехи 6 флаг только хранится в регистрации (`VisibleToEditor`); шапка по нему не фильтрует, пункт виден любой роли с чтением |
| Комментарии | Пометка для человека. Колонки RO, E, L, приоритеты, Атлас и меню ЕО она не меняет |

## Исключения

Пилот фреймворка записи (TransportLegs, веха 7/8) **не** равен первому Gate C (домен Ставки).

Схлопывание Вид транспорта + Тип транспорта + Тип 3 ур. — отдельная задача **после полной миграции (веха 14 / Gate D)**; до этого переносим три справочника as-is.

## Внешние мастера

СВТ — мастер тарифов, логистических плеч и складских ограничений. Редактор и загрузчик не делать там, где в колонках E и L стоит `—`. На Gate C домена источником истины в СВТ объявляются только строки с E не `—`. Строка с E = `—` флипом не охватывается: данные извне остаются у внешнего мастера, СВТ их читает. `AverageRateLevel3` — производная ставок, отдельного флипа нет; пересчёт в волне записи «Ставок» пишет результат в те же легаси-таблицы, до Gate D.

Колонка «Комментарии» — пометка для человека. Состав работ, меню и приоритет она не задаёт.

Карточка АСВ НСИ (код `78`, выгрузка архитектурного контекста от 2026-09-03): IBM MDM, Oracle, промышленная эксплуатация, категория «стратегически нецелевая».

Данные ЦБД остаются мастером ЦБД — домен «Интеграция с ЦБД». Нужен ли редактор или загрузчик у строки — по колонкам E и L этой строки.

## Меню

Меню верхнего уровня имеет короткие подписи (требование к backlog 3.2.4). Полное имя — описание домена, не подсказка в интерфейсе:

| Пункт меню | Описание домена |
|---|---|
| Ставки | Ставки |
| Паритеты | Паритеты |
| Маршруты | Маршруты |
| Продукты | Продукты |
| Склады | Склады и ограничения |
| МК | Матрица каналов |
| ЦБД | Интеграция с ЦБД |
| Вспомогательные | Вспомогательные справочники |

После вехи 6 редактор домена (сейчас эта роль называется «Единое Окно») видит только справочники с **меню ЕО = да**. С **меню ЕО = нет** — только **Админ**, в том же домене (отдельного админ-дерева нет). До вехи 6 шапка по этому флагу не фильтрует.

Пункты внутри домена в шапке идут по алфавиту подписи на текущем языке интерфейса. Колонка «Пр. RO» задаёт приоритет работ внутри домена, не порядок меню. Очередь RO для API Атласа — колонка «Атлас» и раздел ниже (параллельный поток, выше остатка «Ставок»). Выгрузка профилей приоритетов ставок Атласу не нужна — в пилоте профиль «Импорт в CRM». Шапка собирает пункты из вкладов модулей (`AddCatalogMenu`). Целевой порядок доменов справочников: Ставки, Паритеты, Маршруты, Продукты, Склады, МК, ЦБД, Вспомогательные. Домен «Заявки» в это меню не входит: это сервис 4, не справочник. Домен без вкладов не показывается. До вехи 6 флаг «меню ЕО» хранится в регистрации и меню по роли не фильтрует.

Колонка «Имя» — имя сущности легаси (`EntityInfo`; у большинства строк оно совпадает с `PrimitiveEntityInfo`). Модуль в коде может называться иначе: `Rates` → `TransportRate` (ключ `TransportRateId`), `TransportLegs` → `TransportLeg` (ключ `TransportLegId`). Если в легаси-имени есть `_`, модуль без подчёркивания, первая буква каждого сегмента заглавная: `TransportType_level_3` → `TransportTypeLevel3`. Правило — skill `add-reference-book`, шаг 0.

Исключение: `Contractor` в колонке «Имя» — имя `EntityInfo` (id 2054). Примитив — `LegalType`, представление — `vw_LegalType`. `vw_Contractor` устарело.

## Очередь RO для API Атласа (коды smart-lookup)

Параллельный поток тиража RO: **выше** остатка домена «Ставки», не подчиняется порядку доменов. Порядок — для обобщения в smart-lookup (продукт → группа, тип транспорта → вид и т.д.) и для UI Атласа по кодам запроса.

| Атлас | Имя | Название | Домен | Код smart-lookup |
|---|---|---|---|---|
| 1 | Currency | Валюты | Вспомогательные | `currencyCode` |
| 2 | ProductGroup | Транспортные группы | Продукты | транспортная группа (обобщение) |
| 3 | MTR | Продукты | Продукты | `productCode` |
| 4 | TransportType_level_3 | Типы транспорта (3 уровень) | Маршруты | `transportTypeCode` |

Модули очереди в СВТ 2.0 есть (релиз 2.3.48): `Currency`, `ProductGroup`, `MTR`, модуль `TransportTypeLevel3` (в реестре `TransportType_level_3`). Currency и TransportTypeLevel3 — разовый снимок, без watermark-sync. ProductGroup и MTR — watermark-sync.

## Заявки

Домен сервиса, не справочников: строк в таблицах скоупа нет, отдельного пункта меню справочника нет. Легаси `TransportRequest` и `MassiveRequest` сюда не переносятся.

Модуль — [backlog.md](backlog.md) 4, сразу после тиража чтения, только новый контур, без write-through. Свой Gate A/B (сверка и ОПЭ) входит в приёмку 4 и не входит в волну записи семи доменов. Gate C нет: источник истины легаси для заявок не флипается.

До вехи 6 создать заявку может любая роль `dbo.Role`, обработать — `Window Users`. С 6 целевая модель принята: создаёт Р-03 «Инициатор заявок», обрабатывает Р-06 «Обработчик заявок», Р-07 «Читатель» заявки не создаёт. Ставку в справочник домена «Ставки» Р-06 пишет только вместе с правом администратора этого домена (Р-02). Кто назначен обработчиком поименно, полный перечень действий по заявке и связь с KPI — пробелы аналитики 4.1.1.
