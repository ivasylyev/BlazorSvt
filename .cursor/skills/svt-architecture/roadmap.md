# I. План трансформации СВТ

## 1. Контекст и цели

### 1.1. Бизнес-контекст

- СВТ — MDM по управлению логистическими маршрутами, тарифами и складскими ограничениями.
- Масштаб: ~100 справочников; 10–100 полей; до ~2 млн записей (цель новой системы — до 10 млн); пакетная загрузка до 30 тыс. строк.
- **Скоуп переноса:** ~60 используемых справочников; **~40 вне скоупа** (не используются бизнесом).
- Пользователи: ~300 на чтение, ~10 на запись.
- Интеграции: ~30 потоков.
- Языки UI: ru / en.

### 1.2. Цель трансформации

- Снизить стоимость разработки и сопровождения (TCO).
- Обеспечить масштабируемость объёмов данных и расчётов.
- Устранить архитектурные ограничения легаси, препятствующие развитию.
- Цель — не «чистая архитектура ради стека».

### 1.3. Стратегия

- **Strangler Fig**: поэтапное замещение, общая БД на переходный период, параллельная работа старой и новой систем.
- **SoT (источник истины) = легаси-таблицы до cutover.**
- **Exit dual-run** — волнами (по справочнику/группе): выключение старого UI после сверки и приёмки; запись по-прежнему write-through в легаси-таблицы.
- **SoT flip** — в конце, после опытно-промышленной эксплуатации и административного решения бизнеса (вместе с финальным отключением легаси, MVP 2.0). Не раньше полного (или последней волны) exit dual-run.

| Решение | Преимущества | Риски | Меры |

| Один конвейер для редактора и загрузки Excel | • Одни правила<br>• Нет расхождения ручного ввода и пакета | • Сложный общий каркас | • Общие проверки и команды<br>• N строк файла = N сохранений |
