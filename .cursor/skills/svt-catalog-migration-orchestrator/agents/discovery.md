# Роль: discovery

Сначала прочитай `{AgentsDir}\common.md`.

Задача — собрать факты о справочнике и заполнить `{WorkDir}\spec.md` по шаблону `{AgentsDir}\spec-template.md` (раздел 1 уже заполнил classify, кроме заголовков, кода API и периода). Код и SQL в репозитории не пишешь. Твоя главная ценность — вынести спорные решения наверх **до** кода, с данными.

## Твои файлы

Только `{WorkDir}\spec.md` и `{WorkDir}\discovery-report.md`. В репозитории ничего не меняешь, в базе только `SELECT`.

## Что читать

- `add-reference-book/SKILL.md` — «Шаг 0», «Соглашения об именовании», «Стабильный словарь с enum» (если `Class=simple`).
- `add-reference-book/discovery.md` — §1–7 и «Таблица алиасов сущностей». Выполняй discovery по этим разделам; resx и SQL не пиши (§5 `discovery.md` (resx) — у csharp). Раздел «Кто читает легаси» в конвейере исполняешь ты: ты и read-only субагент, и его родитель. Вложенных субагентов не запускай, модель не выбирай. Сверку 2–3 полей повторным запросом и имена членов enum по §7 делаешь сам; SQL, C# и эталон — у ролей sql и csharp.
- `add-reference-book/grid-column-glossary.md` — заголовки грида.
- `.cursor/skills/svt-architecture/catalogs-scope.md` — строку справочника и строки словарей, на которые он ссылается. Замечание «поменять столбцы» не выполнять — в раздел 9.
- Эталон DTO/`GridSettingsService` — по классу из `add-reference-book/SKILL.md`, только стиль имён.

## Шаги

1. Проверь скоуп и класс (`Class` из параметров и раздела 1). По данным класс другой — «ВОПРОСЫ».
2. Подтверди `{LegacyName}`, PED и легаси-view по шагу 0 / разделу 1; таблицу PED — по `OBJECT_DEFINITION` view.
3. В разделе 1 spec заполни пустые строки: заголовок RU / EN (из MDM), код API, период действия. Заполни разделы 2–5 и 7 spec по §1–7 `discovery.md`: короткий/длинный списки, типы, переводы, ссылки, enum, миграция (`VersionPrefix`, содержимое папки — в батче номера пересчитает sql).
4. Только `simple`. Enum уже есть — сверка неархивных строк с ним, пункт 3 раздела «Стабильный словарь с enum» `add-reference-book/SKILL.md`. Расхождение — «ВОПРОСЫ». Enum нет — раздел 5 заполни членами по §7 `discovery.md` (Id, имя, Display RU/EN) и вынеси состав в раздел 9 на подтверждение.
5. Только `complex`: раздел 6 spec — источники каскада по §6 `discovery.md` и правилам sync в `add-reference-book` (данные для решения: `MAX(LastChangeDate)`, изменения за 3 года, fan-out, есть ли `RowVer`, как пишет `stg.Load*`). Чужие `PopulateAffectedKeys` на основную таблицу — в раздел 6. Предложение по умолчанию — каскад включить.
6. Раздел 9: всё, что требует решения, — с вариантами, данными и предложением. Раздел 8 оставь пустым.

## Чего не делать

Не выбирать молча там, где правило допускает варианты. Не переносить колонки, типы и длины из похожего справочника — только из запроса или DDL. Правила ссылок, enum и эталонов не пересказывай в spec — исполняй по `add-reference-book`.
