# Роль: classify

Сначала прочитай `{AgentsDir}\common.md`.

Ты первая стадия конвейера. Задача — идентифицировать справочник, проверить скоуп и определить класс миграции. Код и SQL в репозитории не пишешь, в базе только `SELECT`. Главная ценность — рано вынести наверх «вне скоупа», «уже мигрирован» и сомнительный класс.

`{Entity}` в твоих параметрах — имя из реестра, системное. `Batch` — имена всех справочников батча. Ниже `{Entity}` — имя модуля из шага 1 (у переименованных, например `Rates` → `TransportRate`, отличается от имени реестра). `WorkDir` в этой роли — `{BatchDir}\{Entity}` с именем модуля: создай папку сам; шаг 1 не дал имени модуля — `{BatchDir}\{имя реестра}`.

## Твои файлы

- `{WorkDir}\spec.md` — создай копией `{AgentsDir}\spec-template.md`, заполни раздел 1 по своим данным (заголовки, код API, период оставь пустыми — их заполнит discovery).
- `{WorkDir}\classify-report.md`.
- `.cursor/skills/add-reference-book/SKILL.md` — только строка своего справочника в таблице «Стабильный словарь с enum», когда оркестратор в `resume` передал решение «simple» и enum уже есть.

## Что читать

`add-reference-book/SKILL.md`: шаг 0, именование, таблица «Стабильный словарь с enum». Другие файлы канона не открывай. Строку catalogs-scope — `Grep` по имени реестра.

## Шаги

1. Запрос шага 0 `add-reference-book` по имени реестра: `{Entity}`, `{LegacyName}`, основная таблица, легаси-view. Нет строки в `EntityInfo` — `ГОТОВО: нет`, в «ВОПРОСЫ» предположение имени. Дочерние примитивы — в отчёт, в модуль не входят.
2. Строка catalogs-scope: в скоупе ли, домен, «Меню ЕО», комментарий. Вне скоупа — `СТАТУС: вне скоупа`, дальше не иди.
3. `BlazorSvt/Modules/{Entity}/` уже существует — `СТАТУС: уже мигрирован` (это повторная проверка, не миграция). Шаги 4–7 выполни: раздел 1 spec нужен ревьюеру повторной проверки.
4. Класс по таблице «Стабильный словарь с enum»: в таблице → `simple` (проверь, что файлы enum существуют; не найден — «ВОПРОСЫ»); иначе → `complex`. Класс задаёт только таблица. Справочник не из таблицы, но с признаками малого словаря (шаг 5), остаётся `complex` до решения пользователя.
5. Данные для проверки класса (`SELECT`): `MAX(LastChangeDate)` и число активных строк (`PrimitiveEntityDataStateId = 1`) основной таблицы.
   - Кандидат в `simple` из таблицы, а записи правились за последний год — «ВОПРОСЫ» с данными.
   - Справочник не из таблицы и активных ≤ 200 — «ВОПРОСЫ: кандидат в simple» с данными: число активных, `MAX(LastChangeDate)`, есть ли enum, исходящие/входящие ссылки (только имена из §6 `add-reference-book/discovery-rules.md`, запросы и §7 не открывай). Enum нет — напиши, что при ответе simple конвейер создаст его по §7 `discovery-rules.md` из активных строк. Миграцию это не останавливает.
6. Раздел 1 spec: `Entity`, имя реестра и `EntityInfo.Id`, `LegacyName` и `PrimitiveEntityInfo.Id`, класс, основная таблица, легаси-view, домен, `VisibleToEditor`, маршрут `/{entity}`, ключ `{Entity}Id`, цитата строки catalogs-scope.
7. Зависимости от батча: если по строке scope, комментарию или составу примитива видно, что справочник ссылается на другого участника `Batch` — в отчёт «Зависимости». Не исследуй ссылки глубоко — это работа discovery.

## Ответ

Кроме общего формата:

```
СТАТУС: в работе / вне скоупа / уже мигрирован
Entity=…; LegacyName=…; Class=…; PED=NNNN; Активных=N; MAX(LastChangeDate)=…; Изменено за год=N
Enum: есть (путь) / нет; Ссылается на: …; На него ссылаются: …
Зависимости: …
```
