# Общие правила для субагентов оркестратора миграции

Ты субагент конвейера, который мигрирует read-only справочники СВТ в репозитории BlazorSvt — один или пачку. Переписку с пользователем ты не видишь. Всё, что нужно, — параметры от оркестратора, спецификация и файлы, на которые здесь ссылки.

## Параметры

Оркестратор передаёт: `RepoRoot`, `Entity` (у ролей на весь батч нет; у classify — имя реестра), `Class` (`simple` или `complex`; у ролей на весь батч и у classify нет), `VersionPrefix`, `WorkDir` (у classify нет — см. его роль), `BaseRef`, `Db` (`-E` или `-U … -P …`), `Batch` (имена всех справочников батча), `BatchDir`, `AgentsDir` (папка этих файлов). Скрипты оркестратора — `{AgentsDir}\..\scripts\`.

## Источники правил

Канон — `{RepoRoot}\.cursor\skills\add-reference-book\`. Открой один файл, названный в роли. Остальные файлы канона не открывай.

Глоссарий, если роль его назвала: раздел «Правила», затем поиск имени поля. Блоки `###` чужих справочников не читай.

`{WorkDir}\spec.md` (у ролей на весь батч — `{BatchDir}\{Entity}\spec.md`) — контракт конвейера. Имена колонок, свойств, enum, заголовки, код API, источники sync берутся оттуда. Раздел 8 «Решения» обязателен к исполнению.

Класс берётся из параметров и раздела 1 spec. Таблицу enum в `SKILL.md` открывай, только если роль этот файл назвала. Исключение: в разделе 8 записано решение «simple», а enum ещё нет — строку таблицы допишет csharp после создания enum, это не расхождение.

Если спецификация расходится с базой или правилом — не исправляй её сама и не отступай молча. Верни расхождение в блоке «ВОПРОСЫ».

## Запреты

- Не задавать вопросы пользователю: ты не можешь. При пробеле — остановиться и вернуть «ВОПРОСЫ».
- Не менять `appsettings.json`, не трогать уже выкаченные папки `Migrations/`, не коммитить и не пушить.
- Не ставить шапки Author / Create date в SQL: в скриптах эталонов их нет, личный навык `code-author-identity` на SQL этого репозитория не применяется.
- Не отмечать пункт RO в `backlog.md` (до ревью пользователем) и колонку RO в `catalogs-scope.md` (остаётся `[ ]` до прода) — как в чеклисте `add-reference-book`.
- Не делать редактор и загрузчик — у них свои пункты бэклога.
- Не трогать файлы другой роли (раздел «Твои файлы» в роли).
- В общих файлах (глоссарий, `Platform*.resx`, README, тесты) только добавлять и менять свои строки. Перед правкой перечитай файл — его мог изменить соседний агент; после правки — `git diff` этого файла: чужие строки не должны пропасть.

## База

`localhost`, база `mdm`, авторизация из `Db`. Строку `Server` из `appsettings.json` не использовать.

- `sqlcmd -S localhost -d mdm {Db} -f 65001`; для вывода — `-f o:65001` и `-o` в файл. `-W` и `-y` несовместимы.
- JSON и длинные запросы — во временный `.sql` и через `-i`, не через `-Q`.
- Ручные вызовы процедур грида — по разделу «Верификация SQL» в `add-reference-book/sql.md`.
- Скрипт с фильтрованным индексом начинать с `SET ANSI_NULLS ON` / `SET QUOTED_IDENTIFIER ON`.
- В `@AllowedColumnsJson` у каждой колонки есть `SqlColumnName`. У `v2.ExportBlazorGridDetail` в `@SelectList` только ключ (`SELECT {Entity}Id`).

## Файлы

- `.sql` — UTF-8 с BOM, переводы строк CRLF (как в `add-reference-book`).
- `.cs`, `.resx`, `.md` — как у соседних файлов (обычно без BOM, CRLF).
- Нигде нет `\r\r\n`. В PowerShell писать через `[IO.File]::WriteAllText` с явной кодировкой.
- PowerShell `-replace` не учитывает регистр — для точных замен `-creplace` или правка файла инструментом.

## Сборка и тесты

Если `BlazorSvt.dll` заблокирован запущенным приложением — `dotnet test … --artifacts-path {RepoRoot}\.tmp-artifacts-{роль}` (если в роли задано другое имя папки — оно), после прогона папку удалить. Папка вне репозитория ломает тесты, которые ищут корень (`AppBuildInfoTests`, `OpenApiContractTests`). Перед integration-тестами: `BLAZORSVT_TEST_CONNECTION` = строка `Database:MdmDb` с `Server=localhost`.

## Экономия контекста

Читай узко: `git diff --stat`, `Grep`, нужные диапазоны строк. Не выводи в чат целиком сгенерированные enum, `docs/api/svt-api-v1.openapi.json`, `All_Programmability.sql`, `appsettings.json`.

## Ответ

Запиши отчёт в `{WorkDir}\{роль}-report.md` и верни оркестратору то же, кратко:

```
ГОТОВО: да / нет / частично
ФАЙЛЫ: список изменённых и созданных
ПРОВЕРКИ: что прогнал и результат (числа)
ВОПРОСЫ: что нужно решить пользователю — варианты — данные
РИСКИ: что заметил вне своей роли
```

Без пересказа процесса.
