# Вехи СВТ в разделе «г» план-графика

Черновик вех → полоска и карточки стрима `p0-СВТ` в HTML. Разделы а/б/в/д/е план-графика и поля уже существующих вех 1а — skill `plan-grafik-md-html`. Порядок доменов, пакеты и оценки — `roadmap.md` навыка `svt-architecture`. Этот навык их не меняет.

## Файлы

| Файл | Роль |
|------|------|
| `.cursor/skills/svt-architecture/atlas-milestones-draft.md` | Что переносить: срок, статус, дорожка, название |
| `docs/docs/План-график Атлас/Логистика_—_эталонный_процесс_и_Атлас_план_график_v24_+_чат_v2_2.html` | Куда писать. Стрим `<details id="p0-СВТ">`, заголовок `г) Вехи: результат и метрики` |
| `docs/docs/План-график Атлас/разделы_0_1а_1б.md` | Снимок после правки. Его пишет `extract.ps1`, руками раздел «г» СВТ туда не набирают |

Шапка черновика: это не канон. При расхождении с `roadmap.md` по порядку доменов, зависимостям старта, номерам пакетов и оценкам верен `roadmap.md`. Из этого навыка дорожную карту не правят.

`_svt_vehi_patch.md` и `_svt_metrics_1a_patch.md` в той же папке — старые заметки. Источник правки — черновик и реплика пользователя в этом разговоре.

## Куда именно писать

Внутри `p0-СВТ` две поверхности. Порядок строк на обеих совпадает с таблицей черновика.

1. Полоска: `<div class="p0-tl p0-blue" aria-label="Вехи СВТ 2.0">`. Один пункт — одна строка:

```html
<div class="p0-tl-i done"><b>11 / 2026</b><strong>Название из колонки «Веха»</strong><span>передача · выполнено</span></div>
```

2. Карточки: следующий `<div class="p0-cards">`. Одна веха — один `<div class="p0-card p0-blue">`.

`extract.ps1` читает полоску регулярным выражением без переносов внутри пункта: `<div class="p0-tl-i КЛАСС"><b>…</b><strong>…</strong><span>…</span></div>`. Перенос внутри пункта или лишний тег — строка пропадёт из снимка MD. Карточка для extract: `p0-ch` с `<b>`, затем `p0-ct`, затем блоки `p0-cm` / `p0-cr`. Следующая карточка или `<h4` идёт сразу после закрывающего `</div>` карточки.

Шаблон карточки:

```html
<div class="p0-card p0-blue"><div class="p0-ch"><b>11 / 2026</b><span class="p0-tag">развитие</span><span class="p0-st ok">выполнено</span><span class="p0-lane">передача</span></div><div class="p0-ct">Название из колонки «Веха»</div>
  <div class="p0-cm"><span class="p0-l">Результат и метрика</span>пробел</div>
  <div class="p0-cr"><span class="p0-l">Ресурс</span>пробел</div></div>
```

Карточку стабилизации с таблицей «было / стало» не переформатировать, если её строка в черновике не менялась. Правка соседних карточек — точной заменой их HTML, чтобы таблица не попала в замену.

В `p0-СВТ` нет вложенного `</details>`. `apply.ps1` ищет первый `</details>` после `id="p0-СВТ"`. Вставлять `</details>` внутрь стрима нельзя.

## Соответствие колонок

| Черновик | Полоска | Карточка |
|----------|---------|----------|
| Срок | `<b>` | `<b>` в `p0-ch` |
| Статус | класс пункта и текст после ` · ` | текст `p0-st` |
| Дорожка | текст до ` · ` | `p0-lane` |
| Веха | `<strong>` | `p0-ct` |

Название копируется из ячейки «Веха» и на полоску, и в `p0-ct`. Сокращать полоску своим заголовком нельзя: у старых нетронутых вех короткая подпись уже есть («Стабилизация выполнена» при длинной карточке), её оставляют. У вехи, которую только что переименовали или добавили, на полоске то же название, что в черновике.

Орфография ячейки сохраняется. В черновике зафиксировано «Утвержден» без «ё» — в HTML пишется так же.

Класс полоски и бейдж — как уже стоит на карточках этого стрима:

| Статус | Класс `p0-tl-i` | Бейдж |
|--------|-----------------|-------|
| выполнено | `done` | `p0-st ok` |
| в работе | `work` | `p0-st plan` |
| ориентир | `later` | `p0-st plan` |
| план | `later` | `p0-st plan` |

В CSS есть `.p0-st.work` (янтарный). На карточках СВТ он не используется. «в работе» остаётся `p0-st plan`. Класс полоски при этом `work`: синяя подсветка пункта.

Колонки «тип» в черновике нет. У нетронутой карточки `p0-tag` не меняют. Новая веха в том же отрезке, что соседи ноября–декабря 2026 (до первой карточки с тегом `запуск`), получает `развитие`: так помечены все карточки СВТ до запуска. Тег `запуск` или `тираж` новой вехе 2026 года не присваивают.

Подпись полоски: `дорожка · статус`. Исключение уже в файле — стабилизация: `ИТ · Васильев, Подоплелова, Ершов, Петренев · выполнено`. Её не переписывают, пока строка стабилизации в черновике не изменилась.

Счётчик в шапке стрима: `вех N` в `<span class="p0-ss">`. N — число `p0-tl-i` внутри `p0-СВТ`. После склейки двух вех в одну N уменьшается на 1, после добавления увеличивается на 1. Если склеек и добавлений поровну, N прежний (в сессии 16.11.2026 две склейки и два добавления оставили 23). `задач M` этим навыком не трогают.

## Склейка

Пользователь называет две существующие вехи и новое название, срок, статус, дорожку.

- В черновике две строки становятся одной, остальные перенумеровываются. В HTML номера нет: два пункта полоски и две карточки становятся одним пунктом и одной карточкой.
- Веху ищут по названию. Дата в реплике может потерять цифру: «0 / 2026» при тексте «передан Кудрявцеву» — это строка «10 / 2026» «Эталонный процесс … передан … Кудрявцеву».
- Старый текст карточки, который противоречит новому статусу, в новую карточку не переносят. Так ушли формулировки «На 12.11.2026 не согласован», «это передача, не согласование», «Кудрявцев его не утвердил», «выходит из отпуска», «работа на ближайшие две недели», показатель «Ролей в системе: 3. Цель вехи — утверждённый набор Р-01…Р-04».
- Новую цифру, версию документа или критерий приёмки не сочиняют. В черновике метрики нет. «Результат и метрика» — название вехи. Фразу «Передача выполнена» пишут только если пользователь сказал, что передача выполнена.
- «Ресурс» — фамилии, которые уже стояли на склеиваемых карточках и всё ещё относятся к новой формулировке. Поручения, которые пользователь не закрыл, снимают. С эталона оставлены Подоплелова Е. (описание), Васильев И. (передача), Кудрявцев В. (утверждение). С ролей оставлены Кудрявцев В. и Подоплелова Е. Сняты «сотрудник бизнеса от Кудрявцева» и «Васильев И. (группы доступа)»: первое было про черновик юзкейсов, второе — про сопоставление после утверждения, пользователь этого не называл сделанным. Если фамилий не осталось — `пробел`.

## Новая веха

- Строка в черновике и пункт полоски с карточкой в месте, которое назвал пользователь («перед Создан первый прототип»). Если место не названо — по сроку среди строк черновика.
- Похожая более поздняя веха остаётся. «Сформирован план работ» (11 / 2026, в работе) добавлен рядом с февральскими «Перечень работ сформирован» и «Перечень работ утверждён», потому что слова разные (план и перечень) и склейки не было.
- «Результат и метрика» и «Ресурс» новой вехи — `пробел`, пока пользователь их не дал.
- Дорожку, которую пользователь не назвал, новым именем не называют. Берут дорожку заменяемой вехи. У новой вехи со статусом «в работе», вставленной рядом с вехой дорожки `бизнес`, в той сессии поставили `бизнес` и написали об этом в ответе. `передача` и `бизнес ✔` ставят только если так сказано. По примечанию черновика `бизнес ✔` — веха, которую в карточке закрывает утверждение бизнеса.

Сокращение из реплики в HTML не тащат. В черновик и в карточку попадает имя домена, как оно уже стоит в таблице («Заявки на расчёт транспортировки»), а не «транс-ки». «3 - х ролей» в черновике записано «3 ролей».

## Что не менять вместе с вехами

- Абзац `p0-note` под заголовком «г)». В нём по-прежнему: сделано по ИТ — стабилизация; сроки по плану-графику стрима (Васильев И., 12.11.2026); после перечня работ домены внахлёст; после июня 2027 остальные домены одной вехой; сроки после 02 / 2027 — ориентир. Абзац меняют, когда пользователь меняет эти фразы.
- Блоки а, б, в, д, е, ж того же стрима. Открытый вопрос в «ж» («Какие роли выходят в первый прототип — пробел») может устареть после новой вехи. Его закрывают отдельной просьбой.
- Другие стримы.
- Раздел 1а, `V12_SPEC`, `TASKS`, пайплайн 1б. У СВТ там свой список с кодами `24.*` (в снимке 1б у стрима было 34 вехи). Раздел «г» — статический HTML и с `V12_SPEC` не связан. Пока пользователь не попросил 1а, расхождение оставляют и называют его в ответе.
- Синие классы `p0-blue`, `p0-blued`, `p0-blue-mark`.

## После правки HTML

`apply.ps1` раздел «г» не пишет. `ApplyP0` обновляет ящики а/б/в и секции д/е. Запускать apply, чтобы «опубликовать» полоску и карточки, не нужно: он их не соберёт. После точечной правки HTML apply для а/б/в/д/е полоску не затирает.

Снимок MD обновляют так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".cursor/skills/plan-grafik-md-html/scripts/extract.ps1"
```

Проверка: в `разделы_0_1а_1б.md` у `{p0-СВТ}` в «Полоска вех» и «Карточки вех» есть новые названия, сроки и статусы. Число пунктов полоски в HTML равно `вех N` в шапке стрима и числу строк таблицы черновика.
