## Кольцо версии 2.7

Обод — шесть шагов. Ш7, Ш8 и Ш9 на обод не возвращать.

| Шаг | Название | Человек |
|-----|----------|---------|
| Ш1 | Получение данных. Чего нет в системах-источниках, человек вводит вручную | Р-02: ручной ввод и файл у узкого круга. Р-03 создаёт заявку в сервисе 2.5, не как шаг кольца |
| Ш2 | Техническая проверка. Автомат пускает строку или отклоняет. Обмен, редактор и файл читают один список | — |
| Ш3 | Бизнес-проверка. Человек утверждает или отклоняет строку, которая технически верна и по бизнес-правилу под вопросом. Если таких строк нет, шаг пропускается | Р-02 своего справочника; по всем справочникам — Р-01. Правку проверки включает Р-04 |
| Ш4 | Расчёт и применение. Новые значения из принятой базы и дата действия. Отдельного шага «актуальный срез» нет | — |
| Ш5 | Контроль полноты. СВТ показывает, каких данных не хватает. Передачу это не останавливает | Р-02 заводит недостающее; эскалация — Р-01 |
| Ш6 | Передача потребителям. СВТ отдаёт данные сама | Р-04 отвечает за доставку |

| Ядро | Название | Человек |
|------|----------|---------|
| П8 | Консистентность уже записанных данных. Поток не стоит | Р-04. Замену данных ставит задачей Р-02 |
| П8 | Сверка план-факт. СВТ данные не правит. Решение бизнеса может сменить правила П1 или П7 | Сигнал — источнику и владельцу справочника. Р-01 видит общий дашборд |

Точек Ч-1…Ч-4 нет: человек называется по шагу. К-01 — жёсткая проверка на Ш2, К-02 — мягкая проверка (Ш2, решение на Ш3). Этими кодами клиентов не обозначать. На схеме красная выноска — Ш3, строка ждёт; жёлтая — Ш5, нехватка, данные идут дальше. Агент — второй веха, только если бизнес признает его целесообразным: правила меняются часто и данных много. Иначе правила меняет поддержка в коде, данные вносит бизнес вручную. Бизнес-плановые и спотовые ставки дефлятором не умножаются. Порядок типов — справочник «Приоритеты типов ставок», его ведёт владелец продукта. Для авто: фактическая, договорная, индикативная. В ЦБД уходит бизнес-плановый срез, зафиксированный на дату.

### Кто работает в СВТ

Модель — со встречи с Кудрявцевым В. Р-06 и Р-07 добавлены на встрече 12.11.2026 и помечены гипотезой. Смотреть все справочники может любая роль; кому нужен только просмотр, получает Р-07. Право менять — набор доменов, не роль на каждое сочетание. Автоматика ролью не является.

| Код | Роль | Права | Где на кольце |
|-----|------|-------|---------------|
| Р-01 | Владелец продукта | Все бизнес-права по всем доменам, кроме ИТ. Ведёт справочник «Приоритеты типов ставок». Формулы и пороги — гипотеза | Ш3 по всем справочникам, эскалация Ш5, дашборд П8 |
| Р-02 | Администратор домена | Правка выданных доменов: ставки; паритеты; маршруты, плечи и лидтаймы; продукты; склады и ограничения; матрица каналов; интеграция с ЦБД. Сотрудники компании и аутсорс («Северсталь»). Около 50 человек с правом менять. Аутсорсу только «Ставки» — гипотеза | Ш1 ввод и файл, Ш3 и Ш5 своего домена |
| Р-03 | Инициатор заявок | Создаёт заявки, данные не вносит | Сервис заявок 2.5, не шаг кольца |
| Р-04 | Администратор ИТ, он же техническая поддержка | Пользователи, роли, настройки, интеграции, служебные справочники. Целостность и доставка | Ш3 включает правку проверки, Ш6 доставка, П8 консистентность |
| Р-06 | Обработчик заявок | Смотрит справочники. Очередь заявок, которые умный подбор не закрыл. Ставку в справочник пишет только вместе с Р-02 на домен «Ставки». Кто назначен поимённо — пробел | Не шаг обода |

Матрица «роль × шаг» — только в `SVT-roli-i-puti.html`. Права по доменам в эталоне — раздел 5.2. В идеальный процесс их второй раз не копировать. При расхождении кодов верен раздел 5 эталона 2.7.

### Роли доступа сегодня

Четыре роли с 2019 года, руководство ред. 32. Переход — раздел 5.4 эталона:

- **Единое окно** — правка всех справочников, больше 50 пользователей. Переходит в Р-02 на нужные домены и в Р-01 на все. Ручной запуск передачи в ЦБД и ЕСД уходит в автоматику.
- **Логист по виду транспорта** — вносит ставку плеча по заявке. Переходит в Р-06; чтобы завести ставку в справочник, нужна и Р-02 на домен «Ставки» — гипотеза.
- **Инициатор** — переходит в Р-03.
- **Администратор** — переходит в Р-04.

## Обмен СВТ с Атласом: пилотный API

Факт кода на 20.10.2026, не текст HTML. В СВТ 2.0 есть пилотный API для фронтенда Атласа, только чтение: все справочники СВТ 2.0 (поиск, карточка, выгрузка Excel) и умный подбор ставки с тем же результатом, что у CRM (К-03). Атлас ходит служебной учёткой и передаёт пользователя; права — роли этого пользователя в СВТ. Записи через API нет. Устройство, принятые риски и вопросы к команде Атласа — skill `svt-architecture`, `architecture.md` §6.6.1; задачи — backlog 5.2.

На прод пилот ещё не вышел: согласования класса данных, сети и сертификата открыты (backlog 5.2.7). Поэтому в `SVT-idealnyy-process-2.7.html` СВТ пока нет в порядке подключения к шине Атласа. Менять это только после выхода пилота на прод и по отдельному решению пользователя. В тексты кольца API не вписывать как действующий обмен.

Номинации и квоты утверждает ЗЛУ, сумму свыше 200 млн — тендерный комитет. Это решения вне СВТ. Номинации авто, подтверждённые ЗЛУ в Логинете, на Ш3 повторно не утверждаются. Договорная ставка — тип ставки в справочнике ставок СВТ, не ставка закупки вне справочника.
