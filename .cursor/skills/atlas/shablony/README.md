# Шаблоны Атласа

Копия папки рабочего стола `АТЛАС ШАБЛОНЫ`. Это исходники метода и материалы логистики. В документы СВТ их текст не переносить: шаги, даты, КТ, фамилии и коды чужого кольца остаются в этих файлах.

Два слоя:

- Корень — документы программы «Атлас логистики» (as-is, executive, роли, ФТТ, ЗнИ, план-график, найм, автоматизация).
- `2/` — промпты метода кольца и один уже собранный пакет процесса «план-факт» (не кольцо СВТ).

Заполненный пакет план-факта, который уже лежал в навыке, — [../etalon-to-dev/README.md](../etalon-to-dev/README.md). Его шаги Ш1…Ш8 на СВТ не класть.

## Промпты — что соблюдать

Промпт 1 и единый промпт расходятся в одном месте. Промпт 1 пишет целевой документ сразу, ячейки «как сейчас» оставляет плейсхолдерами и текущее состояние в диалоге не запрашивает. Единый промпт требует явный запрос текущего состояния и описывает два документа. Для прохода 1 по СВТ побеждает промпт 1: не выдумывать as-is. Полную пару Документ 1 / Документ 2 не собирать, пока пользователь не попросил. Живой материал СВТ — HTML, не новый docx, пока пользователь не попросил файл.

Промпт 2 собирает пакет из уже готового executive. Фамилии в этот пакет не подставлять: роли «менеджер процесса» и «лидер цифровизации от ИТ». В шаблонах владельцам промптов нет. Интеграции заполняются по документам и интервью, не по логам.

Промпт 3 ничего не решает сам. Три типа расхождений: человек с человеком (Т1), человек с логами (Т2), человек с эталоном (Т3). Пробел остаётся пробелом. Целевой слой меняется только по Т3. Эталон владельцу шага до синтеза не показывать. Журнал решений назад не переписывать.

`2/00_Индекс.md` — карта пакетов план-факта (сигнал, прогноз, лимиты). На кольцо ведения модели СВТ эти Ш1…Ш8 не переносить.

Пока пользователь явно не попросил проход, шаблоны владельцам СВТ не рассылать и синтез не запускать.
