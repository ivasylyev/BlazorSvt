# grill-with-docs

Интервью по дереву решений. Первый ответ — разбор темы, за ним пачки по 3–5 вопросов, самые значимые первыми. Факты из репозитория и канона агент смотрит сам.

Постановка этим скилом не пишется. Код не начинается. Канон и глоссарий меняются только после явного «да» на конкретную формулировку.

## Когда применять

- «Погриль», «grill-with-docs», «grill me», «проведи интервью», «спроси меня»

Разработка справочника, рефакторинг и оценка архитектуры остаются у `svt-architecture` и `svt-migrate-catalog`. Запись файла постановки — у `to-spec`.

## Перед вопросами

Прочитай таблицу «Канон» в `svt-architecture/SKILL.md`. Из канона открой только файлы, которые ведут тему. Тема — правила, навыки или команды агента: прочитай `.cursor/README.md` и `.cursor/docs/writing-pages.md`.

Глоссарий заранее не читай. Термины из реплики проверь поиском по `.cursor/skills/svt-architecture/glossary.md`: совпадение со смыслом, который расходится с репликой, — пункт «Противоречия». Файл целиком открывай, только когда дописываешь строку.

Термин в вопросах и рекомендациях — как в глоссарии. При первом упоминании нового термина — «русский перевод (English)», дальше короткий английский термин.

Факт, который есть в коде, каноне или глоссарии, не спрашивай. Поиск фактов в коде отдай параллельному explore-агенту; первая пачка его не ждёт.

Для изменения уже существующего пути прочитай его в коде до первой пачки: что он уже возвращает, пишет и каким тестом покрыт. Реплика, которая этого выхода не учитывает, — пункт «Противоречия», не вопрос. Этот просмотр первая пачка ждёт. Остальной поиск фактов по-прежнему у explore-агента.

## Разбор входа

Первый ответ — разбор темы, до вопросов. Три списка, в каждом не больше 5 пунктов, пустой список не выводится:

- **Противоречия** — внутри реплики, с каноном, с кодом, с глоссарием. Каждое со ссылкой на файл.
- **Неполнота** — чего не хватает по чеклисту: цель и критерий готовности; скоуп «в / вне»; фаза Gate и write-through; единый pipeline UI и batch; объёмы (10 млн, 30 тыс.); доступ; интеграции и идемпотентность; аудит; обратимость. Нерелевантное измерение пропускается молча.
- **Допущения** — что реплика считает очевидным, но нигде не записано.

Сразу за разбором — первая пачка вопросов. Противоречия идут первыми.

## Пачки

Пачка — 3–5 вопросов. Порядок: противоречия, затем по значимости = число зависящих решений × цена отката.

Зависимый вопрос не откладывается: задавай его с пометкой «(если В1 = ➡️)». Если пользователь отверг рекомендацию по В1, перезадай только помеченные вопросы.

Формат:

```
❓ **В1** ⚠️ — **<заголовок>**: <текст; зачем спрашиваю — какой пробел или противоречие>

➡️ <рекомендуемый ответ>

---

❓ **В2** — **<заголовок>** (если В1 = ➡️): <текст>

➡️ <рекомендуемый ответ>
```

Формулируй так, чтобы «да» принимало рекомендацию. ⚠️ — противоречие с каноном или дорогой откат. «Да всем» не закрывает ⚠️: нужен отдельный ответ.

После пачки — строка **По умолчанию**: мелкие решения, которые принимаются, если нет возражения.

Размытый ответ не принимай: уточни в следующей пачке. Ответ пользователя жди до следующей пачки.

Постоянное умолчание, не вопрос пачки. По умолчанию поведение на C# входит в задачу вместе с unit-тестом. Ручной осмотр файла, лога или экрана этот тест не заменяет. Факт, который виден только на стенде, остаётся допущением и не закрывает поведение, которое тест видит.

## Журнал

После каждой пачки — журнал на 3–6 строк: Закрыто / Открыто / Пробел / Допущение. Следующая пачка строится из журнала, дерево заново не пересобирается.

После 4 пачек предложи закрыть интервью; оставшееся — явные пробелы.

## Термины

Единственный файл терминов — `.cursor/skills/svt-architecture/glossary.md`. Корневой `GLOSSARY.md` и `GLOSSARY-MAP.md` не создавать.

Новая строка дописывается в существующую таблицу «Термин | Пояснение». Вступление файла не переписывать. Что попадает в таблицу, решает это вступление: узкий английский термин и русское пояснение. Отдельный фильтр «только уникальные понятия предметной области» не применять.

Глоссарий — словарь. Постановка, план, чеклист, схема и пути к коду в него не пишутся.

Строку пиши только после «да» на эту формулировку. До «да» термин остаётся в разговоре.

## Решения канона

Предлагай дописать файл канона, только когда верны все три условия:

1. Откатить дорого.
2. Без контекста решение удивит.
3. Был реальный выбор из альтернатив.

Файл бери из таблицы «Канон» в `svt-architecture/SKILL.md` — тот, который эту тему уже ведёт. Новый вид протокола и каталог `docs/adr/` не создавать. Правку пиши после «да» на конкретный абзац. До «да» решение остаётся в разговоре. В постановку его переносит `to-spec`; постановка — снимок, не процедура.

Уже записанный принцип архитектуры в файл не копируй.

## Конец

Интервью закончено, когда каждая ветка либо закрыта ответом, либо явно оставлена пробелом. Итог — четыре блока: решения, риски, допущения для проверки, пробелы. Спроси, общее ли понимание. После «да» постановку не пиши и код не начинай: постановка — отдельная команда `to-spec`.
