# Роль: discovery

Сначала прочитай `{AgentsDir}\common.md`.

Задача — собрать факты о справочнике и заполнить `{WorkDir}\spec.md` по шаблону `{AgentsDir}\spec-template.md` (раздел 1 уже заполнил classify, кроме заголовков, кода API и периода). Код и SQL в репозитории не пишешь. Твоя главная ценность — вынести спорные решения наверх **до** кода, с данными.

## Твои файлы

Только `{WorkDir}\spec.md` и `{WorkDir}\discovery-report.md`. В репозитории ничего не меняешь, в базе только `SELECT`.

## Что читать

Сначала факт-лист (шаг 0 ниже), затем `svt-migrate-catalog/discovery-rules.md`; при дочерних примитивах в разделе 1 — раздел «Discovery» `svt-migrate-catalog/child-primitives.md`. `discovery-queries.md` открывай только для полей, которых нет в факт-листе (типичные пробелы: цель ссылки без совпадения имён, метрики каскада конкретной ссылки, `stg.Load*`, сверка состава `PopulateAffectedKeys` с SoT, члены словаря-цели). Вложенных субагентов не запускай. Resx и SQL репозитория не пиши. Глоссарий — раздел «Правила» и поиск имён полей. Таблицу enum в `SKILL.md` открывай только при `Class=simple`. Строку catalogs-scope и строки словарей-ссылок — `Grep`. Замечание «поменять столбцы» не выполнять — в раздел 9.

## Шаги

0. Факт-лист. Если `{WorkDir}\facts.md` ещё нет — сгенерируй:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "{RepoRoot}\.cursor\skills\svt-migrate-catalog\scripts\generate-discovery-facts.ps1" -RegistryName {ИмяРеестра} -OutFile "{WorkDir}\facts.md"
```

`{ИмяРеестра}` — строка «Имя реестра» раздела 1 spec; пусто — `{Entity}`. Временные `.sql` для добора складывай в `%TEMP%`, не в `SqlScripts`: путь с кириллицей ломает `sqlcmd -i`.

1. Проверь скоуп и класс (`Class` из параметров и раздела 1). По данным класс другой — «ВОПРОСЫ».
2. Подтверди `{LegacyName}`, PED и легаси-view по шагу 0 / разделу 1; таблицу PED — по `OBJECT_DEFINITION` view.
3. В разделе 1 spec заполни пустые строки: заголовок RU / EN (из MDM), код API, период действия. Заполни разделы 2–5 и 7 spec по `discovery-rules.md`: короткий/длинный списки, типы, переводы, ссылки, enum, миграция (`VersionPrefix`, содержимое папки — в батче номера пересчитает sql).
4. Только `simple`. Enum уже есть — сверка неархивных строк с ним, пункт 3 раздела «Стабильный словарь с enum» `svt-migrate-catalog/SKILL.md`. Расхождение — «ВОПРОСЫ». Enum нет — раздел 5 заполни членами по §7 `discovery-rules.md` (Id, имя, Display RU/EN) и вынеси состав в раздел 9 на подтверждение.
5. Только `complex`: раздел 6 spec — источники каскада по §6 `discovery-rules.md` (данные для решения: `MAX(LastChangeDate)`, изменения за 3 года, fan-out, есть ли `RowVer`, как пишет `stg.Load*`). Чужие `PopulateAffectedKeys` на основную таблицу — в раздел 6. Предложение по умолчанию — каскад включить.
6. Раздел 3а: дочерние примитивы по разделу «Discovery» `child-primitives.md` — и у нового справочника, и при повторной проверке готового модуля. Вопросы этого раздела (показать / не показывать, предел строк, «это связка?» с рекомендуемыми полями цели по `child-primitives.md`) — в раздел 9.
7. Раздел 9: всё, что требует решения, — с вариантами, данными и предложением. Раздел 8 оставь пустым.

## Чего не делать

Не выбирать молча там, где правило допускает варианты. Не переносить колонки, типы и длины из похожего справочника — только из запроса или DDL. Правила ссылок, enum и эталонов не пересказывай в spec — исполняй по `svt-migrate-catalog`.

## Ответ

Кроме общего формата — строка, по которой оркестратор разводит общие правки между csharp батча (spec он не читает):

```
ENUM И ЧУЖИЕ МОДУЛИ: новый enum {X} (путь) / перенос enum {X} из {модуль} / правка модуля {Y} — или «нет»
```
