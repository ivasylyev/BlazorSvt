# Формат `разделы_0_1а_1б.md`

## Frontmatter

```yaml
---
source: <имя html>
sections: [0, 1а, 1б]
extracted: YYYY-MM-DD
---
```

## Раздел 0

- `## 0. …` + первый абзац → `<section id="pres0-sec"> … <p>` (intro)
- `### Кольцо логистики` — справочный текст (apply сейчас **не** переписывает кольцо; меняй в HTML или расширь apply)
- Стримы:

```markdown
#### Название стрима {p0-КОД}
- highlight: blue   # опционально
- meta: …

##### а) Как работает сейчас
текст или список `- …`

##### б) Проблематика
…

##### в) Что хотим сделать
…

##### г) Вехи: результат и метрики
> примечание

###### Полоска вех
| Дата | Веха | Класс | Подпись |

###### Карточки вех
**дата — заголовок**
- тип: …
- **Результат и метрика:** …
- **Ресурс:** …

##### д) Ресурсный план стрима
##### е) Пересечения со смежными командами
##### ж) Открытые вопросы и где нужна помощь
```

`apply -What p0` обновляет **а/б/в/д/е** внутри существующего `<details id="p0-…">`.  
Карточки, полоску вех и блок **ж** apply пока не пересобирает целиком (риск сломать таблицы/разметку) — правь точечно в HTML или доработай скрипт.

## Раздел 1а

- Intro → `#streams-sec`
- На каждый стрим:

```markdown
### Стрим `КОД`: Название
- Ответственный бизнеса: …
- ИТ-лидер: …

| Код | Тип | Дата | Веха | Ответственный | Шаги кольца |
| `24.6` | развитие | 13.10.26 | … | … | 1,7,8 |

<details><summary>Метрики…</summary>
#### `24.6` — …
- Критерий/метрика: …
</details>
```

`apply -What v12` для каждой строки таблицы с **существующим** `code` пишет в `V12_SPEC`:

| Колонка MD | Поле JSON |
|------------|-----------|
| Веха | `t` |
| Дата | `d` |
| Ответственный | `own` |
| Тип (запуск/тираж/развитие/веха) | `type` (`del`/`roll`/`dev`/`std`) |
| Критерий/метрика | `metric` |

Колонку «Шаги кольца», `roster`, `mtdef` apply не меняет.

## Раздел 1б

- Intro → `#pipe6-sec`
- Список стримов — справочный; UI строится скриптом из `V12_SPEC` + `TASKS`
- Чтобы сменить пайплайн, обнови вехи в **1а** (`-What v12`) или задачи `TASKS` в HTML отдельно
