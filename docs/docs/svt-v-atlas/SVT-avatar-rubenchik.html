Это и есть его ок на реинжиниринг. Не на замену платформы. Два процесса рядом: SQL/инциденты — одно, идеальный процесс и правила — другое. Смешать в «трансформацию СВТ» — вернуть разговор туда, откуда он уже вышел.

0. Два процесса, не один

Контур А · техника

Дедлоки, иерархия таблиц, предел SQL-запросов, инциденты интеграций. Делает Ершов / Васильев / Корякин. ИИ здесь — разбор динамического SQL и гипотезы упрощения внутри SQL Server. Потом, не сейчас — PostgreSQL.

Это выполнение технических требований к живущей системе. Не открывает L3. Не кормит идеальный процесс цифрами «на сколько быстрее станет Blazor».

Контур Б · знание

Обследовать текущие бизнес-правила и описать, как система должна работать. Это реинжиниринг процесса методом Атласа. СВТ — первая, потому что стоит в начале эталона логистики. С этим он ок.

Идеальный процесс, «как сейчас», 34 правила, шаблоны владельцам шагов — этот контур. Не смешивать с дедлоками и не называть целевым проектом, пока контуры не сойдутся.

Сходятся контуры только на Ш4 сторителлинга: предел техники с А плюс актуальные требования с Б. Тогда карточка, L3, бюджет с Каплей. До этого — два отчёта, два адресата, две формулировки. Идеальный процесс — артефакт контура Б, не обоснование контура А.

1. Кто это

Роль в нашем контуре

  • Антон Владимирович. Смотрит сторителлинг до Дениса и Марата.
  • Не владелец процесса СВТ (это Капля). Не бизнес-лидер (Кудрявцев). Не заказчик Атласа логистики (Аветисов).
  • Разводит два процесса и не даёт склеить их в один проект «трансформация».
  • Союзник контура Б (обследование правил, реинжиниринг). Союзник контура А, пока это дожим SQL, а не смена платформы. Противник, если слышит одно вместо другого.

Как принимает решение

  • Сначала: это инцидент (контур А) или дыра в знании (контур Б)?
  • Потом: есть ли конкретный адресат (Ершов, Корякин), а не «дайте ресурс».
  • Гипотезу SQL проверяют на текущей базе, не проектом трансформации.
  • Атлас — параллельно технике, не вместо неё и не внутри неё.
  • Карточка проекта и бюджет — когда оба контура дали результат, и Капля подписывает бизнес-необходимость.

3. Голос критика: что он скажет про наш идеальный процесс

Ниже — не «замечания по стилю». Это то, чем он снимет документ с повестки 30.10, если услышать первым.

Удар 1. «Вы склеили два процесса, которые я развёл»

Он ок на реинжиниринг: обследовать текущие правила и описать идеал методом Атласа. Он ок на SQL: дожать гипотезу внутри SQL Server. Он не ок, когда кольцо, Blazor, MCP и «целевой проект» лежат в одном файле — это снова одна «трансформация» вместо двух контуров.

Ответ заранее. «Техника — отдельный контур, Ш2 закрыт. Это контур знания: обследование правил и идеальный процесс. L3 не открываем, пока контуры не сойдутся».

Удар 2. «Где правила из SQL, которые я просил снять ИИ?»

Промпт 1 Атласа: правило живёт в одном месте, формула «событие → правило → действие», текущее состояние не выдумывается. Промпт 3: без анкеты и логов шаг не синтезируется. Он это усилил приказом: снять правила из динамического SQL.

У нас: 34 нарушения (цифра из бэклога), в плане для руководителей — 4 примера, в идеале — КД-01…КД-36 плюс КД-МК. Это выглядит как полный реестр. Это не реестр. Это спроектированные контроли. Он отличит за 30 секунд.

Ответ заранее. Таблица на один экран: сколько правил снято из кода / из руководства / ещё неизвестно. Честно: из SQL — 0. Следующий такт — промпт 2а по проверкам Ш4, не «ещё красивее кольцо».

Удар 3. «Эталон показали раньше синтеза»

Метод пакета запуска: эталон (промпт 1) → шаблоны владельцам шагов (промпт 2) + логи (2а) → синтез по шагу (промпт 3). Эталон сотрудникам до синтеза не показывают. Мы уже написали «как сейчас» по гайду и бэклогу и готовы нести это на утверждение 30.10.

Ответ заранее. «Документ — проход 2 промпта 1 для владельца продукта и для вас. На исполнителей не выносим, пока нет пакета шаблонов. К 30.10 просим зафиксировать рамку (СВТ = источник П3 и Д-14), а не приёмку шагов».

Удар 4. «Два кольца Ш, вы сами путаете историю»

Сторителлинг: Ш1 стабилизация → Ш2 SQL → Ш3 Атлас → Ш4 целевой проект. Идеальный процесс: Ш1 событие … Ш9 сверка. Он ведёт совещание по первому. Если открыть второе без переводчика — «вы не умеете рассказывать».

Ответ заранее. Один слайд-переводчик: «Ш3 сторителлинга = вот это кольцо ведения модели. Внутри него шаги тоже называются Ш — это метод Атласа, не фазы проекта».

Удар 5. «20 идей — это бэклог без хозяина и без инцидента»

Он запретил просить ресурс «в общем виде». Волна 2: «нужен бюджет» на тендер, НХТК, Логинет, умную проверку. Без: какой инцидент, какой потребитель, какое правило в SQL, кто в бизнесе подпишет карточку.

Ответ заранее. На встречу с ним — только волна 0 (решения Капли без разработки) и явное «L3 не просим». Волну 2 не класть, пока нет карточки проекта.

Удар 6. «Человек в четырёх точках — красиво. Кто утверждает правило сегодня?»

В-19 / P0: регламента утверждения нет. Единое окно у 50+. Роли целевые нарисованы, интервью не было. По Атласу HITL — только дорогое/необратимое. Пока Ч-2 не именной (Карпов / Кудрявцев / Миназова на конкретный домен) — это картинка, не процесс.

Ответ заранее. Не защищать роли. Сказать: «Это вопрос владельцу процесса, без него Ш5 не существует. Просим вас не пускать эталон логистики на утверждение, пока В-19 открыт».

Удар 7. «Стыки без полей — не контракт»

Промпт 1: стык = события, данные, чьё правило. Мы написали «ставка на дату / норматив Д-14». Нет состава полей, частоты, что будет, если СВТ молчит. Для него это снова «взаимодействие».

Ответ заранее. «Полный состав — интеграционная карта, её нет. На 16.10 просим одну строку в задаче 4.1: СВТ — система-источник П3 и Д-14 по всем видам транспорта, копии в Атласе нет».

Удар 8. «Агенты и MCP — не то ИИ, которое я заказывал»

Он заказал Claude/Cursor, чтобы вытащить правила из динамического SQL. А-13 «предлагает сменить правило» — для него мода Атласа. Автоматику СВТ (подбор, дефлятор, ночная синхронизация) он примет как «список того, что уже есть», если у каждого правила появится хозяин. Иначе: «вы автоматизировали незнание».

Ответ заранее. На встрече с ним А-13, MCP, git-правил не произносить. Произносить: «ИИ уже использовали на SQL запросов (Ш2). Следующее применение ИИ — снять правила валидации из динамического SQL, как вы и сказали».

  3. 3:00. Кольцо СВТ одним рисунком: не перевозка, а жизненный цикл версии ставки/срока. Человек — в проверке, утверждении, дыре, смене правила. Не агенты.

  5. 7:30. Что просим не от бюджета, а от него: (а) не смешивать Атлас логистики с проектом замены СВТ; (б) вписать СВТ источником П3 и Д-14 до 16.10; (в) не утверждать эталон логистики при открытом В-19.

  7. 11:00. Молчание. Если пошёл в архитектуру — вернуть: «это знание, не платформа».
