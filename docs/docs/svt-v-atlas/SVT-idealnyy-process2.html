1. Картина процесса

1.1. Модель

СВТ ведёт: ставки, паритеты, маршруты, плечи и лидтаймы, складские ограничения, матрицу каналов.

Каждое изменение проходит полный цикл — шаги Ш1…Ш9: получение данных, обработка, передача потребителям и контроль.

  • Ш1 Получение данных — СВТ получает данные из систем-источников, а то, чего нет ни в одной системе, человек вводит вручную. Формат ставок СВТ приводится в соответствие с форматом ставок Логинета.
  • Ш2 Проверка данных — СВТ проверяет данные по одним и тем же правилам, откуда бы они ни пришли.
  • Ш3 Утверждение исключений — человек решает, пропустить или отвергнуть строку, которую проверка посчитала подозрительной.
  • Ш4 Расчёт производных значений — СВТ считает из принятых данных производные значения: дефлированные, средневзвешенные и бизнес-плановые ставки, паритеты, лидтаймы.
  • Ш5 Ввод в действие — новые данные начинают действовать с указанной даты, прежние уходят в архив.
  • Ш6 Передача потребителям — СВТ сама отдаёт действующие значения системам-потребителям.
  • Ш7 Контроль полноты — СВТ показывает, каких данных не хватает, и человек их дозаводит или даёт сигнал источнику: так начинается новый цикл.
  • Ш8 Контроль целостности — СВТ проверяет, что уже записанные данные корректны и согласованы, а ошибки исправляет администратор ИТ новым циклом.
  • Ш9 Сверка план-факт и сигнал источникам — СВТ сравнивает действующие значения с фактом и сообщает о расхождении системе-источнику.

Шаги опираются на единые проверки, реестр исключений, журнал загрузок, отчёт о полноте и расхождениях.

1.2. Источники

Основной путь — автоматический обмен. Ручной ввод и ручная загрузка для всех потоков, кроме мультимодальных перевозок, — дополнительный путь, его сокращают. Для мультимодальных перевозок ручной файл — основной путь только на первом этапе, дальше он дополнительный.

  • Логинет или Озеро данных (что именно — пробел). Отдают тендерные ставки авто с номинациями и все фактические ставки. Модель данных Логинета, около 30 столбцов, переносится в СВТ целиком.
  • ATI через Озеро данных (где хранятся данные — пробел). Отдаёт индикативные ставки авто.
  • Умная логистика (нужна ли как источник — пробел). Ещё один источник индикативных ставок авто: есть API и договор.
  • Калькулятор НХТК (уточнить у Насти Сироткиной — пробел). Отдаёт железнодорожные ставки и расстояния.
  • Картографический сервис (какой именно — пробел). Отдаёт расстояние между отправлением и назначением плеча для авто по России.
  • Система отслеживания машин (на Яндексе, уточнить — пробел). Отдаёт фактический лидтайм авто.
  • Внешние порталы. Teustat, MSC, Феско, CMA, Maersk, Drewry и другие. Отдают данные для паритетов. Teustat — через интерфейс; можно ли забирать данные иностранных порталов автоматически — пробел, возможно, останется загрузка Excel.
  • Почта (согласовать с бизнесом — пробел). Еженедельный файл складских ограничений. На первом этапе его разбирает автоматический алгоритм, на втором — агент и заносит в систему.
  • Ручной ввод бизнеса. Договорные ставки, дефляторы и период факта для бизнес-плана, коэффициенты распутицы, ручная корректировка бизнес-плановых ставок.
  • АСВ и ERP. Отдают контрагентов, узлы, продукты, курсы и склады.

1.3. Обработка данных

Пришедшие данные проходят одинаковые проверки вне зависимости от источника (интеграции, ручного ввода и загрузки файла). Данные приходят в виде независимых друг от друга строк. Жёсткая проверка отклоняет строку. Мягкая проверка отправляет её человеку, и только если возникло исключение. Новое значение действует с указанной даты, прежнее уходит в архив.

СВТ рассчитывает ставки всех типов с применением коэффициентов дефлирования и распутицы. Рассчитывает бизнес-плановые ставки из других типов ставок. Рассчитывает средневзвешенные ставки в различной гранулярности (усредняя по контрагентам, по регионам и т. д.). Также СВТ считает паритет, лидтайм авто с корректировкой по факту и лидтайм ЖД. Подробности — в строке Ш4.

После этого данные уходят потребителям.

1.4. Сервис заявок

Кроме ведения модели, в СВТ есть сервис: по заявке на расчёт ставки СВТ подбирает ставку из модели. Заявка бывает на обычную ставку и на массовую. Заявки не входят в модель: это запрос к данным модели, а не данные. пробел Модуль заявок переработать: упростить порядок работы с заявкой и связать её со справочником паритетов — много заявок приходит по паритетным направлениям, и ставки там часто уже есть.

Сегодня подбор ищет средневзвешенную ставку 3 уровня, не индикативную, и при неудаче расширяет поиск есть сегодня. Нет ставки до конечного узла — ищет по региону, затем по стране. Нет ставки с нужным продуктом — ищет по транспортной группе, в которую входит продукт. Нет ставки с нужным типом транспорта (например, авто фура 20 т) — ищет по виду транспорта «авто», куда входит и, скажем, «авто цистерна». За 2025 год — 3 750 заявок. Правила пересобрать и расширить по годовой истории необработанных запросов CRM. Пример со встречи: клиент назван по-разному, но все знают, что это Тобольск; продукт формально из другой группы, но по сути относится к наливной химии. Ответ либо точный, либо «похожая ставка», которую специалист подтверждает или заменяет своей. Цель — 95% заявок закрываются автоматически, 5% — действительно новые ставки. На втором этапе подбор заменяется агентом, набор правил которого бизнес меняет сам. Если подбор ставку не нашёл, она проходит Ш1–Ш6 и становится значением справочника для всех, а не только для инициатора.

1.5. Потребители

СВТ — мастер-система по ставкам, маршрутам, плечам и лидтаймам, складским ограничениям и матрице каналов. Системы-потребители получают данные через автоматическую интеграцию без ручного вмешательства. Планирование читает маршруты как схему доставки, логистика — чтобы обеспечить мощности.

  • CRM и E-Com. Получают свежие фактические ставки и средневзвешенную ставку, подобранную умным подбором. Нужны для расчёта маржи, цены и затрат. Если ставка ниже рынка, Сибуру приходится доплачивать за перевозку. Если выше, Сибур рискует потерять клиента.
  • ССП. Получает ставки, маршруты, плечи и лидтаймы, складские ограничения. Нужны, чтобы прогнозировать спрос и составить ППР.
  • ЦБД. Получает ставки, лидтаймы и служебные справочники сопоставления узлов и типов транспорта. Ставки нужны для экономического планирования на срок до 15 месяцев, лидтаймы — чтобы прогнозировать EBITDA. В ЦБД уходит только лидтайм, активный на момент отправки, независимо от периода действия ставки. ЖД-ставки — через СВТ гипотеза.
  • Маркетинг (как именно — пробел). Получает ставки из справочника паритетов. Нужны для ценообразования. Забрать нужную ставку из справочника средневзвешенных ставок 3 уровня маркетинг не может факт.
  • ЕСД, программа Оптимакрос. Получает ставки, лидтаймы, параметры складов и складские ограничения. Ставки нужны для календарного планирования, диспетчеризации потоков и учёта загрузки складов. Лидтаймы — для календарного плана отгрузки и остатков по складской сети. Для неоднозначных узлов возможен умный подбор.
  • ЕСД SI (уточнить у бизнеса — пробел). Получает складские ограничения вместе с ЕСД и КПО. Нужны, чтобы проверять исполнимость плана, отгружать только с пригодных складов и использовать закупленные мощности.
  • КПО (уточнить у бизнеса — пробел). Получает складские ограничения, плановый лидтайм доставки и матрицу каналов: квоты, ставки и плановые лидтаймы уходят через программу Оптимакрос. Нужны, чтобы учитывать ограничения отправки железнодорожным и автомобильным транспортом по каналам и направлениям. Рейтинг складов — через СВТ гипотеза.
  • SAP ERP. Получает маршруты и лидтаймы. По маршруту создаёт разнарядки на отгрузку: без маршрута отгрузка клиенту не выполняется. По лидтайму планирует отгрузки — нормативные плановые даты.
  • SAP TMS. Получает ставки и номинации мультимодальных перевозок. Ставки нужны, чтобы заказывать контейнерные поезда и вести мультимодальные перевозки.
  • Озеро данных. Получает сырые данные. Нужны для дашбордов и Контрольной среды.
  • Атлас. Получает все данные, по которым СВТ — мастер-система: ставки, паритеты, маршруты, плечи и лидтаймы, складские ограничения и матрицу каналов. Через интерфейс Атласа выполняются действия этого процесса. Значение — на дату, своей копии Атлас не ведёт.

Ш1Получение данных Отдельной записи о загрузке в СВТ нет: об изменении узнают, когда данные уже в системе. Ключевой пользователь видит большие пачки постфактум и сам сверяет даты загрузок специалистов «Северсталь» с утверждённым графиком. Фактические ставки авто выгружают из Логинета раз в две недели, Python-скрипт переводит файл в формат СВТ. Добавлять столбцы в выгрузку Логинета дорого. Индикативные ставки авто запрашивают у ТЭК или собирают со сторонних ресурсов, например, с Умной логистики. Договорных ставок мало: Суриков присылает их письмом, их вносят вручную. ЖД — 27 файлов НХТК и конвертер. Паритеты специалисты «Северсталь» собирают с внешних порталов вручную по своей методологии, на это уходит 1,3 FTE. Бизнес экспертно проверяет и загружает. По мультимодальным перевозкам итоги тендера анализируют и расставляют номинации вручную. Лидтайм авто по России считают в Excel: расстояние из картографического сервиса подставляют в формулу и вносят в СВТ. Система отслеживания машин сегодня не используется: лидтайм корректируют вручную. По СНГ, Турции и Китаю лидтайм вносит операционная логистика по своей оценке: зимой на Турцию увеличивает до 21 дня, летом снижает. Складские ограничения приходят файлом Excel каждую пятницу, сотрудник переносит их руками. Нагрузка специалистов «Северсталь»: номинации 1,1 FTE, ставки 0,3, лидтаймы 0,1, паритеты 1,3. Автоматически приходят контрагенты, узлы, продукты и курсы из АСВ НСИ, склады из АСВ и ERP. Квоты вводит ЗЛУ руками факт. Пока файл не загрузили, планирование и CRM считают по предыдущему значению: фактические ставки авто отстают до 15 дней. Тендерные пакеты перетирают до 2 100 ставок в месяц. Ошибка в файле входит как факт. Триггер начала процесса — это изменение в системе-источнике. Основной путь — автоматический импорт. Дополнительный путь — ручной ввод или загрузка файла. Формат ставок СВТ приводится в соответствие с форматом ставок Логинета. Пока СВТ не приняла данные, действуют прежние значения. Специалисты «Северсталь» в процессах СВТ участвуют минимально.
  • Тендерные ставки авто и фактические ставки авто. Приходят обменом из Логинета или Озера данных каждый день, на следующий день после утверждённой перевозки. Итоги тендеров приходят вместе с номинациями, плечо всегда из двух узлов, без пограничного перехода. Формат ставок СВТ приводится в соответствие с форматом ставок Логинета, около 30 столбцов. Каждую новую строку Логинета СВТ распознаёт как новую перевозку и забирает её, так все данные факта есть в СВТ и ничего не теряется. В момент прихода работают правила отбора: всплески и малотоннажные перевозки отсеиваются, чтобы одна дорогая машина не исказила среднюю. Логика Python-скрипта Ромы Гордеева переносится в СВТ и дополняется; средневзвешенные ставки считаются на Ш4.
  • Индикативные ставки авто. Приходят из ATI через Озеро данных: данные выливаются в Озеро, СВТ забирает их оттуда, чтобы индикатив был максимально актуальным. пробел Где в Озере хранятся данные ATI — уточнить у Егора Зайцева. пробел С Умной логистикой есть договор и API: нужно ли забирать индикатив и оттуда — уточнить у бизнеса. пробел Как актуализировать, архивировать и сравнивать с рынком ATI — описать с бизнесом.
  • Договорные ставки авто. На первом этапе их вводят вручную из писем экономики логистики, на втором письмо со ставками может разбирать агент и вводить ставку сам гипотеза. Это ставки по тендерам, зафиксированные на год и больше, например, перевозка с месторождений до станций. Их мало. пробел Нужен ли второй этап — решить по объёму ставок и трудозатратам.
  • Индексация ставки инфраструктуры. Приходит как событие индексации.
  • Лидтаймы авто. На Ш1 создаётся плечо. Расстояние между отправлением и назначением и лидтайм запрашиваются на Ш4: для авто по России — у картографического сервиса. Фактический лидтайм авто приходит из системы отслеживания машин по отгрузкам; плановый лидтайм корректируется по нему на Ш4. пробел Что это за система и куда уходят её данные, в Озеро или в другое место, — уточнить у Ивана Фролова. Лидтаймы между нашими предприятиями и другие незаведённые лидтаймы выявляет Ш7. Их заводят вручную новым циклом на Ш1.
  • ЖД. Ставки и расстояния приходят обменом с калькулятором НХТК. пробел В каком состоянии калькулятор, как к нему подключиться и какие типы ЖД-ставок заводить — уточнить у Насти Сироткиной.
  • Лидтаймы ЖД. Лидтайм ЖД считается на Ш4 и зависит от типа отправки: твёрдая (по умолчанию), повагонная, групповая, маршрутная, жёсткая нитка.
  • Мультимодальные перевозки. На первом этапе итоги тендера приходят ручным файлом: это основной путь. Номинация — доля перевозок, которую поручают перевозчику; её считают в Excel вне СВТ. На втором этапе её ведёт СВТ: туда же переносятся обработка данных и другие недостающие атрибуты мультимодальной ставки. Номинации уходят в SAP TMS. пробел Откуда забирать тендеры и фактические ставки — из Логинета или из Озера — уточнить у Ивана Фролова. пробел Откуда приходят итоги тендера — уточнить у Руслана и Айгуль. пробел Переработать ли формат данных, чтобы первое авто-плечо мультимодальной перевозки бралось из авто-ставок, а не заполнялось вручную, или мультимодальная ставка остаётся единой — уточнить у Руслана.
  • Лидтаймы мультимодальных перевозок. Их вносят вручную. пробел Откуда вносят?
  • Паритеты. Данные приходят из разных источников: Teustat, MSC, Феско, CMA, Maersk, Drewry и другие порталы. Teustat отдаёт данные через интерфейс, с него СВТ забирает ставки. MSC, CMA, Maersk и Drewry — иностранные компании: можно ли забирать их данные автоматически и в каком формате, нужно изучить. Возможно, по ним останется загрузка Excel. Ш2Проверка данных Редактор и загрузчик проверяют по-разному. В загрузчике перемешаны проверки старого формата мультимодальных ставок (две строки, склеенные по ключам) и нового (одна строка). Старого формата, по наблюдению ИТ, за последний год не было. Ошибок качества 6–10 в сутки при цели 5. Около половины инцидентов — система приняла то, что бизнес считает ошибкой факт. Стажёр в марте 2025 внёс норматив плеча 37 тыс. вместо 17 тыс.; риск одной ошибки в ППР — до 608 тыс. $. Ловят глазами после того, как строка уже в системе. Старые проверки мешают новым. Обмен, редактор и загрузчик проходят одни и те же проверки: результат не зависит от того, откуда пришла строка. Проверки разделены по категориям.
  • Жёсткие — нарушен бизнес-инвариант, строка отклоняется. Примеры: у плеча не заполнен узел отправления или назначения; абсурдная величина — меньше 300 руб./т или больше 1 млн руб./т; отклонение от рынка в десятки раз.
  • Мягкие — это предупреждение, а не ошибка, строка уходит на Ш3. Примеры: ставка на 50% выше ставки с теми же ключевыми полями за предыдущий период; для авто по России спред от рынка ATI больше 25–30%; резкий скачок значения.
Индексация ставки инфраструктуры предупреждения не даёт: отклонение равно индексации. Для каждого типа ставки и каждого вида транспорта (ЖД, авто, мультимодальный) есть свои дополнительные индивидуальные проверки. Все величины — примеры, пороги задаёт бизнес. Паритеты с мультимодальными ставками не сравниваются: это разные рынки. Квоты матрицы каналов проходят те же проверки: квота на календарный месяц, декады в пределах месячного максимума, ссылки на активные записи. пробел Итоговый список проверок собирается с бизнесом по каждому потоку загрузки; неактуальные нынешние проверки уходят. Проверка данных, которые уже записаны в систему, — отдельный шаг Ш8.
Ш3Утверждение исключений Шага нет. В руководстве справочники меняет роль «Единое окно». Регламента утверждения нет. Ставку по заявке вносит логист по виду транспорта факт. Строку, которую загрузчик не пустил, видит только тот, кто загружал. Подозрительная ставка либо проходит незамеченной, либо её нельзя пропустить, даже если она верна. При автоматическом потоке строки, которые не прошли проверку, теряются. Все строки, которые не прошли Ш2, попадают в реестр исключений с причиной.
  • Строка, отклонённая жёсткой проверкой, видна с причиной. Её исправляют в источнике или загружают заново.
  • Строку с предупреждением ответственный роли этого справочника пропускает или отвергает.
  • Если данные верны, а ошибается проверка, ответственный из реестра запрашивает правку проверки. После правки проверка действует сразу для всех входов.
  • Матрица каналов. Квоты вводит ЗЛУ как первоисточник, отдельного утверждения нет.
Реестр ведёт подробный лог по всем исходам: прошло, предупреждение, отклонено. Без реестра данные из автоматического потока будут теряться.
Ш4Расчёт производных значений Средняя за 3 месяца для ТЗ, спрямление, карта складов — в Excel у ФЭС без версий. В СВТ уже считаются средневзвешенные, дефлятор, синхронизация ставок, округление лидтаймов для ЦБД — внутри базы, формулы не описаны факт есть сегодня. Лидтайм авто по России считают в Excel факт. Средняя ставка по региону — простое среднее по городам, без учёта объёмов. Бизнес-плановые ставки для ЦБД Кудрявцев В. считает в Excel: к фактическим ставкам применяет дефляторы. Дефлятор СВТ он не использует: дефляторы приходят за 1–2 дня до внесения данных, и в Excel получается быстрее. Распутицу считает в Excel: базу ставок на апрель–май умножает на нужные коэффициенты. Ставки, нужные маркетингу, дублируют в справочнике паритетов, связи между справочниками нет факт. Формула ничья. Один и тот же расчёт в Excel и в ночном задании может разойтись, и это увидят только у потребителя. Расчёт идёт после утверждения, из принятых данных. Ставку, пришедшую из Логинета или НХТК, СВТ не пересчитывает. СВТ считает производное: средневзвешенные ставки, бизнес-плановые ставки, распутицу, паритет, синхронизацию групп продуктов, лидтайм авто по России и лидтайм ЖД.
  • Параметры расчётов. Бизнес вручную задаёт период факта и дефляторы для бизнес-плана, коэффициенты распутицы и при необходимости вручную корректирует бизнес-плановые ставки.

Расчёт идёт помесячно на 15 месяцев вперёд. пробел Нужен ли горизонт два года. Ручная корректировка остаётся и по приоритету выше автоматического расчёта. Так дублирующие ставки не расходятся. Это вынужденное исключение: в нормальном мире паритеты и наши ставки живут в разных плоскостях, но маркетинг не может определить, какую ставку из справочника 3 уровня брать на месяц, а из паритетов забирает.   • Лидтайм авто по России. Ш6Передача потребителям Интеграции с восемью системами есть есть сегодня. Маршруты, плечи и лидтаймы уходят в SAP ERP автоматически примерно за 10 минут, ставки в ССП — раз в 5 минут. ССП не получили 2 500 ставок и 29 часов простоя без оповещения. В CRM нет до 400 ЖД-ставок. СВТ — мастер-система по ставкам, маршрутам, плечам и лидтаймам, складским ограничениям и матрице каналов. Сегодня копии есть в Логинете, SAP TMS и частично в SAP: это как сейчас, не устройство кольца. После вступления в силу значение автоматически, без кнопок и дополнительных шагов, уходит в CRM и E-Com, ССП, ЦБД, маркетинг, ЕСД, ЕСД SI, КПО, SAP ERP, SAP TMS, Озеро и Атлас. В ЦБД значения подаются постоянно, ЦБД забирает их, когда готова принять. пробел ЖД-ставки в ЦБД и рейтинг складов для МЛС идут через СВТ. ППР и складской рейтинг читают то значение, которое вступило в силу в СВТ. Корректность сопоставлений — задача нашей стороны, процесс из-за неё не останавливается. пробел Обмен с SAP TMS пересмотреть, возможно готовить данные в формате SAP TMS — уточнить у Руслана. Ручной запуск передачи ролью «Единое окно» уходит. Дошло ли значение до систем, смотрит техническая поддержка; это не шаг бизнес-процесса.
Ш7Контроль полноты В CRM нет до 400 ЖД-ставок. Автоподбор и «Умный подбор ставки» — 90 тыс. запросов за 2025 год; каждый месяц приходит 500–700 направлений, около 5% остаются без ставки. ССП каждую ночь сверяет слепок ЦБД со ставками и плечами СВТ и присылает отчёт о недостающих ставках. Списка направлений без ставки, лидтайма или квоты в СВТ нет. Даты загрузок специалистов «Северсталь» ключевой пользователь контролирует вручную факт. Расчёт клиенту идёт по неверной цене, пока не заметили, что ставки нет. Опоздавший пакет замечают по косвенным признакам. СВТ ведёт отчёт о нехватке данных: направления без ставки, лидтайма или квоты; пакеты, не загруженные к утверждённой дате (журнал загрузок против графика); необработанные запросы CRM; «каталог пуст»; лидтаймы между нашими предприятиями и другие незаведённые лидтаймы. По матрице каналов в отчёте видны направления-каналы без квоты на текущий месяц. Ночная сверка ССП используется как один из источников отчёта. У каждой позиции есть ответственный роли справочника, срок (KPI) и эскалация. Цикл на этом шаге не останавливается. По результату контроля человек вручную вводит недостающие данные — загрузкой Excel в справочник или точечной правкой карточки — либо даёт сигнал системам-источникам. Так начинается новый цикл для тех данных, которых не хватает. За полноту отвечает бизнес.
Ш8Контроль целостности Проверки данных, уже записанных в СВТ, есть есть сегодня. Часть из них появилась после инцидентов, когда некорректные данные прошли мимо входа: например, система пропустила ставки с нулевой стоимостью. Если в АСВ НСИ архивируют узел, паритетные ставки на этом узле становятся неконсистентными факт. Неконсистентные данные уходят потребителям. Проверки перемешаны, часть неактуальна. СВТ регулярно проверяет корректность и консистентность уже записанных данных. Цикл на этом шаге не останавливается. При некорректных данных администратор ИТ корректирует данные или исправляет ошибку в системе. И то и другое начинает новый цикл. Если данные нужно заменить, замена идёт новым циклом с Ш1: например, паритетные ставки на заархивированном узле уходят в архив, а на действующий узел заводятся новые. Матрица каналов. пробел Какие проверки целостности относятся к матрице каналов. Поддержка может задавать бизнесу вопросы, чтобы разобрать инцидент. Нынешние проверки пересматриваются: после наведения порядка на входе часть из них потеряет актуальность, остальные переформулируются гипотеза.
Ш9Сверка план-факт и сигнал источникам В СВТ нет сверки действующих значений с фактом пробел. Расхождение тендера и факта или норматива и фактического лидтайма никто не видит системно. Системы-источники не узнают, что их данные не соответствуют реальности. Цикл на этом шаге не останавливается. СВТ сравнивает действующее значение с фактом: по авто — тендер и факт перевозок из Логинета; по мультимодальным перевозкам — факт, который приходит через 3–6 месяцев; по лидтаймам — фактические лидтаймы. На этом шаге СВТ данные не правит. Корректировка планового лидтайма авто по факту системы отслеживания — правило расчёта на Ш4, а не правка сверкой. Матрица каналов. пробел С чем сверять квоты и каналы и куда уходит сигнал. Расхождение сверх допуска — сигнал системе-источнику и ответственным. В Атласе виден дашборд «красное / зелёное»; на следующем цикле видно, ушло ли расхождение. пробел Допуск задаёт бизнес; формат данных для сверки нужно продумать.

3. Кольцо ведения модели

Тёмные стрелки по часовой — путь каждого изменения: от прихода данных до передачи читающим системам и контроля после неё. Бирюзовый пунктир против часовой — обратная связь: сверка план-факт подаёт сигнал в систему-источник, СВТ данные не правит. Человек останавливает цикл только на Ш3, и только если возникли исключения. Ш7 и Ш8 начинают новый цикл, Ш9 подаёт сигнал. Если исключения не возникли, изменение проходит полный цикл без выхода на человека.

ДоменГруппа справочников одной предметной области: ставки; маршруты, плечи и лидтаймы; продукты; склады и ограничения; матрица каналов; интеграция с ЦБД. Право менять выдаётся по доменам.
Единые проверкиОдни и те же проверки для обмена, редактора и загрузчика. Делятся на жёсткие и мягкие.
Жёсткая проверкаНарушен бизнес-инвариант, например, у плеча пустой узел. Строка отклоняется.
Мягкая проверкаЗначение похоже на ошибку, но может быть верным, например, ставка на 50% выше прошлого периода. Это предупреждение: строку пропускает или отвергает человек на Ш3.
Реестр исключенийСписок строк, которые не прошли проверку данных, с причиной. Из реестра строку пропускают, отвергают или запрашивают правку проверки.

ПолнотаВсе ли нужные данные есть в СВТ. Отвечает бизнес, шаг Ш7.
ЦелостностьКорректность и консистентность уже записанных данных. Отвечает техническая поддержка, шаг Ш8.
Сверка план-фактСравнение действующего значения с фактом исполнения. СВТ только подсвечивает расхождение источнику и ответственным, шаг Ш9.
НоминацияРаспределение объёма между перевозчиками по итогам тендера.
Средневзвешенные ставкиСредние ставки разных перевозчиков. Вес перевозчика — его номинация.
Средневзвешенная ставка 3 уровняСправочник СВТ. Умный подбор берёт ставку из него. Формула расчёта в руководстве пользователя не описана.
СтавкаЛогистический тариф.
Фактическая ставкаСтавка, по которой перевозка фактически выполнена.
Договорная ставкаСтавка перевозчика, зафиксированная в договоре по итогам тендера на год или больше. Это тип ставки в справочнике ставок СВТ. Таких ставок мало, их вводят вручную.

Считается из ставок наивысшего по приоритету типа, как правило, фактических, за заданный период: средневзвешивается до регионов, к ней применяются дефляторы по группе продуктов, типу транспорта и стране или направлению. Ручная корректировка приоритетнее расчёта.
Скользящее среднееСредняя ставка за окно, например, за неделю или две до текущей даты. Окно сдвигается со временем. Более свежие перевозки могут весить больше.
РаспутицаСезонное ухудшение дорог в марте, апреле и мае. В СВТ — коэффициенты к ставкам и лидтаймам авто по выделенным направлениям, по сути дефлятор внутри года.
Тендерная ставкаСтавка по итогам торгов. В тендере несколько перевозчиков. Ставка связана с номинацией и содержит номер лота.
Паритетная ставкаСтавка доставки от конкурентов до наших рынков сбыта, например, из Китая в Турцию. Считается по методологии из данных внешних порталов. С нашими мультимодальными ставками не сравнивается: это разные рынки.
