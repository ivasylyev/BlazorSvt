## Краткое содержание
Совещание посвящено описанию идеального процесса работы системы СВТ 2.0. Участники обсудили шаги обработки данных, проверку исключений, передачу данных потребителям, а также интеграцию с CRM и сервисом заявок. Дополнительно рассмотрели возможность включения модели логистической сети (МЛС) в контур СВТ.

## Принятые решения
1. Подсветить в модели, что данные без ошибок переходят с шага 2 на шаг 4, не ожидая утверждения исключений на шаге 3.
2. Продумать механизм обработки исключений (по аналогии с заявками): назначение на ответственных, уведомления, алармы при просрочке.
3. Добавить в модель пометку, что паритеты не архивируются.
4. Добавить ночные обновления (полноценную синхронизацию с потребителями) в ядро механизмов целевого кольца.
5. Выделить синхронизацию ставок из шага 4 в отдельный сервис (рядом с сервисом заявок).
6. Добавить в модель интеграцию сервиса заявок с CRM.
7. Упростить процесс создания заявки из CRM: при отсутствии тарифа заявка с предзаполненными полями отправляется в СВТ автоматически, пользователь получает только уведомление (без ручного перехода в СВТ).
8. Указать, что маркетинг в целевой картине получает данные по паритетам из озера.
9. Сформулировать назначение летаймов для ЦБД как «для оценки срока заморозки рабочего капитала», а ставок — «для расчёта плановой EBITDA и максимизации EBITDA компании».
10. Убрать из описания потребителя ЦБД мэппинги узлов и типов транспорта (они живут на стороне СВТ).
11. Включить МЛС (модель логистической сети) в целевую картину как модуль внутри СВТ (пока записать в раздел «Потребители» с пометкой о целевом размещении внутри СВТ).
