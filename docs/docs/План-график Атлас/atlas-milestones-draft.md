## Результаты вех

Текст результата для карточек. Стабилизация в эту запись не входит: её карточка не менялась.

### 2. Эталонный процесс составлен. Утвержден бизнесом

Составлен эталонный процесс СВТ и согласован с бизнесом. Определены роли, контрольные точки, коды этапов, элементы данных и связи с логистикой. Процесс передан ответственным за дальнейшую реализацию.

- Эталонный процесс утверждён бизнесом.
- Документ передан владельцу продукта и команде реализации.
- Роли и контрольные точки этапов 2.7 зафиксированы.

Показатели: согласован один эталонный процесс. Передача выполнена.

### 3. Роли определены и утверждены бизнесом

Определены роли пользователей СВТ и утверждены бизнесом. Для каждой роли определены права на просмотр и изменение данных в зависимости от домена. Р-03 «Обработчик заявок» добавлена на встрече 12.11.2026.

Показатели: утверждён набор системных ролей. Р-03 добавлена на встрече 12.11.2026.

### 4. Сформирован план работ

Подготовлен план работ по СВТ 2.0: определены состав и последовательность работ, зависимости между доменами, ответственные, ожидаемые результаты и контрольные вехи. План сопоставлен с дорожной картой продукта; расхождения с черновым план-графиком Атласа зафиксированы отдельно.

- По каждой ближайшей работе определены ответственный и ожидаемый результат.
- Для каждого домена предусмотрены этапы: юзкейсы, прототип, демо и утверждение, MVP, ОПЭ, ПЭ.
- Определены зависимости между доменами и точками перехода.
- План не содержит неподтверждённых сроков, выданных за утверждённые обязательства.

Показатели: подготовлен один согласованный план работ. Создатели данных: ~10. Статус вехи — «в работе»: согласования ещё нет, согласованный план — итог, к которому веха закрывается.

### 5. Юзкейсы 2 ролей для домена «Заявки на расчет стоимости»

Описаны пользовательские сценарии для двух согласованных ролей модуля заявок. Для каждого сценария зафиксированы инициатор, предусловия, шаги, входные и выходные данные, результат, исключения и способ проверки.

- Описаны сценарии 2 из 2 согласованных ролей.
- Для каждого сценария определён проверяемый ожидаемый результат.
- Сценарии пригодны для проектирования прототипа без дополнительной интерпретации.

Показатели: юзкейсы 2 из 2 ролей. Работают в прототипе: 4 из ~10 создателей данных.

### 6. Создан первый прототип «Заявка на расчет стоимости»

Создан кликабельный HTML-прототип модуля «Заявки на расчёт стоимости», отражающий согласованные сценарии трёх ролей и ключевые переходы между состояниями заявки. Прототип позволяет пройти критические пользовательские пути без доступа к продовым данным и подготовлен для бизнес-демо.

- Покрыты сценарии всех трёх согласованных ролей.
- Критические пользовательские пути проходятся в браузере без технических ошибок.
- Для каждого демонстрируемого сценария указан ожидаемый результат.
- Подготовлен сценарий бизнес-демо.

Показатели: доступен кликабельный HTML-прототип. Прототип находится в непродовом контуре.

### 7. Демо проведено. Прототип «Заявки на расчет стоимости» утвержден бизнесом

Проведено демо прототипа бизнесу под ролями пользователей. Бизнес прошёл согласованные пользовательские сценарии, оставил обратную связь, а прототип доработан по результатам замечаний. Решение об утверждении прототипа и перечень изменений зафиксированы.

- Проведено демо по сценариям всех трёх согласованных ролей.
- По каждому замечанию принято решение: включить в следующую итерацию или отклонить.
- Зафиксировано решение бизнеса об утверждении прототипа.
- Утверждённый объём пригоден для проектирования MVP.

Показатели: 3 из 3 согласованных ролей представлены на демо. Обратная связь бизнеса обработана.

### 8. Среды подготовлены

Подготовлены среды для сборки, проверки и развёртывания MVP заявок. Настроены необходимые компоненты, доступы и конфигурации; выполнена техническая проверка развёртывания и доступа к тестовым данным.

- Все необходимые среды доступны команде разработки и тестирования.
- Развёртывание выполняется по согласованной процедуре.
- Проверены доступы, подключение к базе данных и тестовая сборка.
- Подготовлен план отката и устранения проблем среды.

Показатели: тестовая и демонстрационная среды готовы. Технический smoke-тест успешен. Доступность сред со стороны разработки и тестирования подтверждена.

### 9. MVP заявок на расчёт на проде. Старт передачи в поддержку

Развёрнут ограниченный по функциональности MVP модуля заявок на проде. Он работает на реальных данных, поддерживает ручное создание заявок и автоматически создаёт заявки по запросам CRM/Ecom, для которых умный подбор не нашёл ставку. Начата передача модуля в поддержку.

- Ручные заявки: ~350 в месяц.
- Автоматические запросы из CRM/Ecom: ~9 000 в месяц.
- Доля запросов, закрываемых умным подбором: текущая база ~95%, цель — 98%.
- Автозаявки создаются по каждому промаху подбора.
- Владелец процесса по ставкам видит автозаявку сразу после её создания.
- MVP передан в поддержку в объёме, согласованном для запуска.

Показатели: ручных заявок ~350/мес. Автозапросов CRM/Ecom ~9 000/мес. Умный подбор находит ставку ~95%, цель — 98%. Автозаявки по промахам подбора включены.

### 10. «Заявки на расчет стоимости» выведены в ОПЭ. Готова док-ция для поддержки

Модуль заявок выведен в опытную промышленную эксплуатацию. Пользователи, создававшие ручные заявки, переводятся на работу в Атласе; автозаявки по промахам подбора создаются автоматически. Подготовлена и передана поддержке эксплуатационная документация.

- Автозаявки по промахам подбора включены.
- Целевая доля запросов, закрываемых умным подбором: 98%, текущая база — ~95%.
- Доля промахов «ставка отсутствует»: не более 1%.
- Доля промахов «существующая ставка не найдена подбором»: не более 1%.
- Руководство для поддержки подготовлено и передано.
- Время ответа на заявку контролируется относительно базы «до».

Показатели: ручных заявок ~350/мес. Автозапросов CRM/Ecom ~9 000/мес. Создатели данных в новом контуре: 3 из ~10. Срок ответа сейчас: до суток на простой рейс по России, до трёх суток на мультимодальный.

### 11. «Заявки на расчет стоимости» выведены в ПЭ, переданы на поддержку

Модуль заявок переведён из ОПЭ в промышленную эксплуатацию. Ручные заявки полностью переведены в Атлас, автозаявки обрабатываются автоматически, эксплуатация и поддержка переданы поддерживающей команде.

- Доля запросов, где умный подбор вернул ставку: 98%.
- Доля промахов по причине «ставки нет»: не более 1%.
- Доля промахов по причине «СВТ не подобрало существующую ставку»: не более 1%.
- Качество данных: не более 1.
- Срок ответа и доля автообработки измерены относительно базы «до».
- Документация для поддержки передана.

Показатели: ручных заявок в Атласе ~350/мес. Автозапросов CRM/Ecom ~9 000/мес. Создатели данных в новом контуре: N из ~10.
