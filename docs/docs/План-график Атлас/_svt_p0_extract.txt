  <div class="p0-grid3"><div class="p0-box p0-blue"><h4>а) Как работает сейчас</h4><ul><li><b>Что ведём.</b> СВТ — мастер-система: ставки, маршруты, плечи и лидтаймы, паритеты, складские ограничения, квоты для матрицы каналов. Мы являемся одним из ключевых источников данных для бизнес-планирования. Данные забирают 8 смежных систем.</li><li><b>Как устроено.</b> Коробочное решение с собственными доработками. За шесть лет добавлено 30% нового функционала, 40% исходного не используется, но влияет на стабильность. Около 300 пользователей работают в трёх ролях. Аудит — только по последним изменениям в системе.</li><li><b>Что уже сделали.</b> Устранены повторяющиеся сбои загрузки данных. Раньше загрузка большого объёма ставок вызывала сбой, а несвоевременное внесение данных могло сдвинуть бизнес-планирование компании. Загрузчик стабилизирован и ускорен.</li><li><b>Почему этого мало.</b> Мы устранили самое острое, чтобы система не падала. Процесс неоптимален, система не до конца отвечает потребностям бизнеса: пользователи жалуются, что приходят не те данные или не тогда. Корневая причина не устранена, её можно снять только вместе с переработкой процесса.</li></ul></div><div class="p0-box p0-blue"><h4>б) Проблематика</h4><ul><li><b>Бизнес-правила устарели и расходятся между собой.</b> Бизнес-логика реализована по устаревшим требованиям, не соответствующим текущим потребностям бизнеса. Одна и та же бизнес-логика реализована в трёх разных местах и из-за этого частично неконсистентна. Около половины инцидентов — система приняла то, что бизнес считает ошибкой. Точечная правка корневую причину не снимает.</li><li><b>Ограничения коробочного продукта.</b> Имеются ограничения в коробочном продукте, из-за чего не все потребности бизнеса можно реализовать. Коробочный продукт хорошо предусмотрен для введения справочников и связи между ними, но плохо предусмотрен для workflow (жизненного цикла заявки). Например, заявки и по ставкам, и по паритетным ставкам коробка не предусматривает: для этого нужно переделывать её ядро.</li></ul></div><div class="p0-box p0-blue"><h4>в) Что хотим сделать</h4><ul><li><b>Поэтапная трансформация по методологии Атласа.</b> Процесс и система меняются вместе: бизнес и ИТ идут одним шагом. Только так снимается корневая причина ошибок в данных.</li><li><b>Актуальные бизнес-правила.</b> Выявляем действующие правила, актуализируем их с бизнесом и реализуем один раз для всех входов.</li><li><b>Процесс, согласованный с бизнесом.</b> Описание процесса уточняем с бизнесом, пока по нему можно строить систему. На этом описании собирается часть Атласа для СВТ.</li><li><b>Роли и прототипы — поэтапно.</b> Роли и прототипы выводим в Атлас по мере обследования процесса. Первым — заявка на расчёт стоимости транспортировки: её жизненный цикл коробка не поддерживает.</li></ul></div></div>
