## Задача: read-only справочник Relevance (Актуальность)

### Контекст

**СВТ 2.0** — переписывание MDM тарифов/маршрутов с легаси на **Blazor Server + MS SQL**. Эта задача переносит справочник **только для чтения** (грид, карточка, Excel, API). Редактора и загрузчика в реестре нет.

Источник истины по составу: `.cursor\skills\svt-architecture\catalogs-scope.md`.  
Чеклист: `.cursor\skills\svt-architecture\backlog.md` → пункт **15.10.23**.

### Что сделать

Перенести сущность реестра **Relevance** (EntityInfo **2127**, «Актуальность») как read-only модуль.

Имя модуля — `Relevance`: в имени реестра нет `_`. `{LegacyName}` — имя основного примитива из `EntityStructure`; его не подставлять именем реестра, пока шаг 0 не подтвердит, что они совпадают.

Из реестра, без discovery:

- домен **Паритеты** (`CatalogDomain.Parities`), меню ЕО = да (`VisibleToEditor: true`), маршрут `/relevance`
- сложность Низкая, пр. RO = 3
- комментарий реестра: константы, вспомогательный для паритетных ставок, только чтение. Состава колонок в нём нет
- входит в класс «стабильный словарь с enum»: `RelevanceRu`, `RelevanceEn`. Разовый снимок, без watermark-sync

- грид + карточка + выгрузка Excel
- пункт меню домена **Паритеты**
- разовый снимок из `v2.vw_Relevance_SnapshotSource`. Эталон — `Modules/Currency` и `Modules/RateType` (и их SQL). SyncJob, `sp_Relevance_PopulateAffectedKeys`, RowVer и инициализацию `v2.SyncState` не создавать. В каскад чужих справочников не включать: их гриды показывают enum
- перед генерацией сверить неархивные строки (`PrimitiveEntityDataStateId = 1`) с `RelevanceRu` / `RelevanceEn`: `Id` и состав членов. Расхождение — стоп. Enum не перегенерировать
- API: `AddCatalogApi`, код `relevances` (обычное множественное число skill), домен `Parities`, ключ `HeaderMenu.Relevance`. `CatalogPeriod` передавать только если в list-DTO есть две даты `DateOnly`. Строки в `v2.SyncState` нет, `dataAsOf` будет пустым — это нормально для этого класса

Отдельного согласованного списка колонок нет, в постановку его не додумывать. Короткий список и порядок грида — discovery §1 после фильтра §3. Порядок карточки — §4 после того же фильтра. Атрибут с нулём заполненных неархивных значений в грид и карточку не входит. Дочерний примитив в модуль не входит, пока его явно не включат. Подписи — Dictionary и `grid-column-glossary.md`. Стоп и согласование по skill: пустой заголовок справочника, английский ярлык совпал с системным именем и его нет в глоссарии, неизвестное короткое имя колонки, ссылка без однозначного FK. Согласованное исключение из этого фильтра дописать в комментарий строки `Relevance` в `catalogs-scope.md`. Колонку RO там не отмечать: `[x]` ставится, когда справочник на проде.
