# Дочерние примитивы на карточке справочника — краткое описание навыка

> Снимок на 2026-11-20. При расхождении верны навыки `add-reference-book` и `svt-catalog-migration-orchestrator`.

## Что делает

Навык `add-reference-book` (файл `child-primitives.md`) и оркестратор `svt-catalog-migration-orchestrator` добавляют на карточку справочника (`GenericDetailView`) группы-таблицы дочерних примитивов (child primitive) после групп основного примитива. Работает и при миграции нового справочника из легаси, и на готовом модуле, где таких групп ещё нет.

## Правила

- Ребёнок с `dbo.vw_{Child}` и хотя бы одной неархивной строкой входит по умолчанию. Без view, без неархивных строк или вложенный — не входит, только в отчёт.
- Колонки — короткий список MDM ребёнка после фильтра незаполненных; `Code` всегда. Ссылки разворачиваются в SQL-проекции `v2.vw_{Child}_Detail`: enum или имя.
- Связка (link child) — ребёнок, который почти только ссылается на запись другого справочника. Пользователь подтверждает, что это связка, и выбирает поля связанной записи; они добавляются в таблицу.
- У активного родителя видны строки в состоянии 1, у архивного — 1 и 2. Не больше `Grid:ChildSectionRowLimit` строк, ниже — «Показано N из M».
- Snapshot, sync, API, OpenAPI и полный Excel не меняются. Уже выведенные поля карточки (`STRING_AGG`, колонки основного примитива) остаются.
- Тесты на модуль: unit `{Entity}ChildSectionsTests` (порядок групп, колонки, подписи RU/EN), integration `{Entity}ChildSectionsIntegrationTests` (строки есть, ссылки развёрнуты).

## Как запускать

| Ситуация | Путь |
|---|---|
| Новый справочник | `add-reference-book` или оркестратор — дети входят в обычный конвейер, раздел 3а spec |
| Готовый модуль, нужно добавить таблицы детей | Оркестратор, доработка: classify → discovery → вопросы → sql → csharp → finalize → reviewer |
| Готовый модуль, только проверить | Оркестратор, «проверь {Entity}»: отсутствие группы — дефект, исправление с согласия |

Термины `child primitive`, `relationship child`, `link child` — `.cursor/skills/svt-architecture/glossary.md`.
