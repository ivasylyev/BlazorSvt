## Задача: пагинация, сортировка и фильтры в таблицах дочерних примитивов на карточке

### Проблема

Таблица дочернего примитива (child primitive) на карточке справочника выводит все загруженные строки подряд — до `Grid:ChildSectionRowLimit` (100). Раскрытая группа с десятками строк сильно удлиняет страницу грида.

### Что меняется в работе

**После части 1.** Раскрытая группа-таблица показывает не больше одной страницы строк. Размер страницы тот же, что у грида справочника. Строки листаются пейджером и сортируются щелчком по заголовку колонки. Если все строки помещаются на одну страницу, пейджера нет. Если строк больше предела, под таблицей по-прежнему выводится «Показано N из M» / «Shown N of M».

**После части 2.** В таблице появляется строка фильтров, как у грида справочника. Если все строки помещаются на одну страницу и активного фильтра нет, строки фильтров нет.

### Контекст

- Предыдущая постановка — `docs/tasks/SVT-5309-coefficient-child-primitives.md`. Там «Постраничный вывод в секции» вне скоупа, а в секции нет фильтров и сортировки. Эта задача снимает оба ограничения.
- Текущий вывод:

  - `BlazorSvt/Platform/Grid/Services/DetailChildSection.cs` — секция переводит `TRow` в `IReadOnlyList<string>` через `DisplaySelector`;
  - `BlazorSvt/Platform/Grid/Models/DetailChildTable.cs` — `Headers`, `Rows` (строки-тексты), `TotalCount`;

- Грид справочника — `BlazorSvt/Platform/Grid/Components/GenericGrid.razor`: `Grid` из BlazorBootstrap с `AutoHideFiltering`, размер страницы из `IGridPageSizeService` (`GridPageSizes`, ключ localStorage `GridPageSize`, один на все гриды).
- Локальная копия BlazorBootstrap — `blazorbootstrap/`: `AutoHidePaging` (`Components/Grid/Grid.razor`), `AutoHideFiltering` (`Utils/GridFilterUtility.ShouldShowFiltersRow`), фильтр на клиенте — `request.ApplyTo(Data)` → `Extensions/ExpressionExtensions.cs`.

### Что сделать

#### Часть 1 — пагинация и сортировка

**Platform**
- Таблицу дочернего примитива выводит вложенный `Grid` из BlazorBootstrap. Строки передаются через `Data` и обрабатываются на клиенте.
- SQL и `DetailChildDataService` не меняются: предел `Grid:ChildSectionRowLimit`, `TOP` по `Id` и `COUNT` остаются.
- Секция отдаёт типизированные строки `TRow` и настройки колонок вместо строк-текстов. Контракт `DetailChildTable` меняется соответственно.
- В `DetailSetting` добавляется выражение сортировки (`SortKeySelector`) от того же свойства, что `Name`. `DetailSettingsBuilder` заполняет его во всех методах `Add*`.
- Колонка выводит значение через `DisplaySelector` — так же, как сейчас.
- Сортировка — по значению свойства, не по подписи, в том числе у enum, «Да/Нет» и статуса архива.
- Размер страницы берётся из `IGridPageSizeService`. Переключателя размера страницы во вложенной таблице нет.
- `AllowPaging="true"`, `AutoHidePaging="true"`, `AllowSorting="true"`, `AllowFiltering="false"`.
- «Показано N из M» / «Shown N of M» (`GenericDetailView.ChildRowsShown`) остаётся под пейджером, если `TotalCount` больше числа загруженных строк. Пейджер листает только загруженные строки.
- Сортировка и номер страницы при каждом раскрытии карточки сбрасываются.
- Секция со строками по-прежнему стартует свёрнутой (`DetailAccordionPlan` не меняется).

**Навык**
- `.cursor/skills/add-reference-book/child-primitives.md` — обновить описание вывода: вложенный `Grid`, пагинация, сортировка.

**Тесты**
- Unit-тесты секций шести модулей (`tests/BlazorSvt.UnitTests/Modules/{Entity}/{Entity}ChildSectionsTests.cs`) переводятся на новый контракт: секция отдаёт типизированные строки, состав и порядок колонок и подписи RU/EN из настоящих resx — прежние.
- Unit-тест `DetailSettingsBuilder` (`tests/BlazorSvt.UnitTests/Platform/Grid/DetailSettingsBuilderTests.cs`): у колонок `Add`, `AddLocalized`, `AddEnum` (обе перегрузки), `AddYesNo` (обе перегрузки), `AddArchiveStatus` выражение сортировки упорядочивает строки по значению свойства из `Name`.

#### Часть 2 — фильтры

Не начинать до явной просьбы пользователя после приёмки части 1.

**Platform**
- Во вложенном `Grid`: `AllowFiltering="true"`, `AutoHideFiltering="true"`.
- Фильтр каждого типа ведёт себя так же, как фильтр того же типа на гриде справочника:
  - строка — поиск по вхождению без учёта регистра;
  - дата — сравнение так же, как после `GridDateTime.NormalizeFilterValue`;
  - enum — выбор из подписей текущего языка;
  - «Да/Нет» и статус архива — выбор из подписей `Platform.resx`.
- Фильтр привязан к свойству из `DetailSetting.Name`.

**Навык**
- `.cursor/skills/add-reference-book/child-primitives.md` — дописать про фильтры.

**Тесты**
- Unit-тест фильтра на клиенте по каждому типу из списка выше, включая nullable enum.
- Unit-тест: для каждой колонки каждой дочерней секции, зарегистрированной в шести модулях, фильтр строится без `ArgumentException("Unsupported property type")`.

### Что не входит

- Серверная пагинация, сортировка и фильтр по всем строкам. Изменение предела `Grid:ChildSectionRowLimit`.
- Переключатель размера страницы во вложенной таблице.
- Сохранение сортировки, фильтра и страницы между раскрытиями карточки.
- Изменение стартовой свёрнутости групп.
- API, снимок OpenAPI, короткий и полный Excel.
- Исправление сортировки enum и «Да/Нет» на гриде справочника, если она расходится с сортировкой по значению.

### Решения

- Пагинация, сортировка и фильтр на клиенте по уже загруженным строкам. SQL не меняется. При строках больше предела результат относится только к первым N строкам по `Id`; об этом сообщает «Показано N из M».
- Типизированные строки `TRow` во вложенном `Grid` с `Data` вместо своей таблицы с ручной сортировкой — тот же компонент и флаги, что у `GenericGrid`.
- Размер страницы — общий с гридом справочника, без переключателя: переключатель внутри карточки менял бы размер страницы основного грида (один ключ `GridPageSize`).
- Фильтры — отдельной второй частью: фильтр на клиенте через `ExpressionExtensions` в проекте раньше не использовался, основная доля риска в нём.
