## Задача: read-only справочник Priority_Rate (Приоритеты типов ставок)

### Контекст

**СВТ 2.0** — переписывание MDM тарифов/маршрутов с легаси на **Blazor Server + MS SQL**. Эта задача переносит справочник **только для чтения** (грид, карточка, Excel, API). Редактор и загрузчик в реестре нужны, но в эту задачу не входят (backlog 9.2.7, 9.2.8). Умный подбор продолжает читать `dbo.vw_Priority_Rate`; переключение на снимок — backlog **5.2.15**.

Источник истины по составу: `.cursor\skills\svt-architecture\catalogs-scope.md`.  
Чеклист: `.cursor\skills\svt-architecture\backlog.md` → пункт **3.3.5**.

### Что сделать

Перенести сущность реестра **Priority_Rate** (EntityInfo **2144**, «Приоритеты типов ставок») как read-only модуль. `Priority_RatesForPlan` (EntityInfo 2103) вне скоупа.

Имя модуля по skill, шаг 0: `PriorityRate` (`Priority_Rate` → без подчёркивания, первая буква каждого сегмента заглавная). `{LegacyName}` — имя основного примитива из `EntityStructure`; его не подставлять именем реестра, пока шаг 0 не подтвердит, что они совпадают.

Из реестра, без discovery:

- домен **Ставки** (`CatalogDomain.Rates`), меню ЕО = да (`VisibleToEditor: true`), маршрут `/priorityrate`
- сложность Средняя, пр. RO = 2
- комментарий реестра: вспомогательный для ставок. Состава колонок в нём нет
- в класс «стабильный словарь с enum» в skill не входит. Отдельного enum PriorityRate в коде нет. Enum этого справочника, найденный при discovery, не перегенерировать: остановиться по правилу skill

- грид + карточка + выгрузка Excel
- пункт меню домена **Ставки**
- watermark-sync (снимок, SyncJob, RowVer, SyncState). Каркас — `Modules/TransportRate` и `SqlScripts/Modules/TransportRate`: Structure, Programmability, SyncJob, модуль. Узлы, продукт, срок действия и WHERE членства TransportRate не переносить. Чужой справочник в Sources — только если проекция PriorityRate его читает. Стабильные словари (RateType, TransportKind, Currency и остальные из таблицы skill) в каскад не входят, даже если проекция читает их Id. RowVer на основную таблицу — по skill, если его там ещё нет
- API: `AddCatalogApi`, код `priority-rates` (обычное множественное число skill), домен `Rates`, ключ `HeaderMenu.PriorityRate`. `CatalogPeriod` передавать только если в list-DTO есть две даты `DateOnly`

Отдельного согласованного списка колонок нет, в постановку его не додумывать. Короткий список и порядок грида — discovery §1 после фильтра §3. Порядок карточки — §4 после того же фильтра. Атрибут с нулём заполненных неархивных значений в грид и карточку не входит. Дочерний примитив в модуль не входит, пока его явно не включат. Подписи — Dictionary и `grid-column-glossary.md`. Стоп и согласование по skill: пустой заголовок справочника, английский ярлык совпал с системным именем и его нет в глоссарии, неизвестное короткое имя колонки, ссылка без однозначного FK. Согласованное исключение из этого фильтра дописать в комментарий строки `Priority_Rate` в `catalogs-scope.md`. Колонку RO там не отмечать: `[x]` ставится, когда справочник на проде.

### Как делать

1. Skill `.cursor\skills\add-reference-book\SKILL.md` целиком.
2. Строка `Priority_Rate` в `catalogs-scope.md` — домен, меню, приоритет.
3. Эталон каркаса — `Modules/TransportRate` и `SqlScripts/Modules/TransportRate`. Разовый снимок RateType/Currency не копировать. Если discovery найдёт существующий enum этого справочника, остановиться по правилу skill.
4. Релизная копия — `Migrations/2.3.49/` (текущий `VersionPrefix`, папка ещё не закрыта). `2.3.48` не менять. `001`–`007` занимает Contractor, `008` — полный снимок `All_Programmability.sql`. Дельта схемы PriorityRate — номера с `009`. Снимок пересобрать из SoT и переименовать в номер после последней дельты: `008` в середине папки не остаётся (так в `2.3.48` после каждой дельты переименовывали снимок, номера старого снимка пустые). В `C:\publish` само по себе не копировать.
5. C# только после наката и проверки SQL на `localhost` / `mdm`.
6. Unit contract-тест DTO и SyncJob; integration smoke грида, карточки и FTS по текстовым полям, которые discovery оставила в гриде; снимок OpenAPI обновить по skill. Умный подбор не менять.
