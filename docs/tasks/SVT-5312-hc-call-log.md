> Рабочая постановка SVT-5312. При расхождении с кодом и skill верны код и skill.

## Задача: журнал вызова /hc

### Проблема

Внешняя система мониторинга вызывает проверку работоспособности раз в 5 минут. В журнале приложения этого вызова нет: маршрут обрывает конвейер до журнала запросов Serilog, а отдельное правило опускает путь до Verbose ниже порога Debug. По файлу `C:/logs/v2` нельзя увидеть, когда вызов дошёл, с каким статусом и от какой учётки, и нельзя собрать статистику для разбора инцидента.

### Что меняется в работе

По вызову, который дошёл до обработчика, в `C:/logs/v2` появляется одна строка. По ней видно время, статус, длительность, адрес клиента, User-Agent и Windows-учётку. Успешные вызовы мониторинга считаются по строкам Debug с шагом 5 минут. Пауза длиннее 5 минут значит, что процесс на вызов не ответил.

### Контекст

Пункта в [backlog.md](../../.cursor/skills/svt-architecture/backlog.md) на журнал этого вызова нет.

Маршрут приложения — `GET /hc` в `BlazorSvt/Host/Program.cs` (`AllowAnonymous`, `ShortCircuit`). Снаружи на стендах путь `/v2/hc`: так настроен роутинг IIS; в конфигурации приложения `PathBase` тоже `/v2`. В руководстве для вызывающих это `GET /v2/hc` без аутентификации API — [svt-api-v1-developers.md](../api/svt-api-v1-developers.md). В снимке OpenAPI пути нет.

Журнал приложения — Serilog, порог Debug, файл `C:/logs/v2`, шаблон с `ShortCorrelationId`. Наблюдаемость — [architecture.md](../../.cursor/skills/svt-architecture/architecture.md) §6.7 и правило `svt-architecture-principles`. Field-level аудит — веха 11, к этому вызову не относится.

Анонимный доступ на IIS выключен. `AllowAnonymous` на маршруте анонимный доступ IIS не открывает.

### Что сделать

- Обработчик `/hc` пишет одну строку Serilog на каждый вызов, который до него дошёл.
- Статус 200 — уровень Debug. Другой статус, который вернул обработчик, — уровень Information.
- Поля строки в одном и том же порядке: метод, путь вместе с `PathBase`, статус, длительность, адрес клиента, User-Agent, учётка.
- Учётка — Windows-имя из уже включённой схемы IIS (`IISServerDefaults.AuthenticationScheme` в `BlazorSvt/Host/Program.cs`). Имени нет — в строке пусто.
- Чтение учётки не отвечает вызывающему 401.
- `ShortCircuit` на маршруте остаётся.
- Заголовок `X-Correlation-ID`, если клиент его прислал, попадает в свойство `ShortCorrelationId` шаблона файла. Нет заголовка — новое значение не создаётся.
- Тело ответа остаётся текстом `healthy` (`text/plain`).

### Что не входит

- Новый URL.
- Снятие `ShortCircuit` и пропуск вызова через остальной конвейер.
- Правка `SerilogRequestLogLevel` и теста `GetLevel_HealthCheck_IsVerbose`.
- Снимок OpenAPI и руководство вызывающих.
- Field-level аудит.
- Ротация `C:/logs/v2`.
- Включение анонимного доступа IIS.
- Ответ 401 из приложения на `/hc`.
- Тело ответа и канал Blazor в строке журнала.
- Имя учётки и User-Agent системы мониторинга в коде.

### Решения

- Строка пишется в журнал приложения Serilog из обработчика. Совпадает с §6.7 [architecture.md](../../.cursor/skills/svt-architecture/architecture.md) и с правилом `svt-architecture-principles`: журнал приложения отдельно от field-level аудита вехи 11.
- Журнал запросов этот путь не видит, потому что `ShortCircuit` выполняет маршрут в `UseRouting`. Место маршрута — `BlazorSvt/Host/Program.cs`. Правило уровня журнала запросов остаётся в `BlazorSvt/Platform/Infrastructure/Logging/SerilogRequestLogLevel.cs`; его описывает раздел «Логирование» правила `svt-development-patterns`.
- Успех в файле — строка Debug. Неуспех, когда процесс не ответил, — пауза длиннее 5 минут. Уровень Information остаётся на статус не 200, который вернёт сам обработчик.
- Учётка читается схемой IIS из обработчика. Различать человека и внешнюю систему нужно по имени, адресу и User-Agent.
- Путь остаётся вне снимка OpenAPI. Контракт HTTP — снимок, §6.6.1 [architecture.md](../../.cursor/skills/svt-architecture/architecture.md).

### Как делать

Скила-процедуры на эту правку нет. Маршрут — `BlazorSvt/Host/Program.cs`. Журнал приложения — правило `svt-development-patterns`, раздел «Логирование»; корреляция заголовка — `BlazorSvt/Platform/Infrastructure/Logging/MiddlewareDecorator.cs`.

### Как проверяем

До файла подтверждено: контракт DTO и SyncJob, integration smoke грида, карточки и FTS и снимок OpenAPI эту задачу не показывают.

Образец существующей проверки — `tests/BlazorSvt.UnitTests/Platform/Infrastructure/SerilogRequestLogLevelTests.cs`, метод `GetLevel_HealthCheck_IsVerbose`. Он проверяет, что журнал запросов для `/hc` и `/HC` остаётся Verbose. Строку обработчика он не видит.

Автоматической проверки факта вызова `/hc` в репозитории нет. Сделанное видно по строке в `C:/logs/v2`.

### Критерии готовности

- [ ] Вызов, дошедший до обработчика со статусом 200, даёт одну строку Debug в `C:/logs/v2`.
- [ ] В строке по порядку видны метод, путь вместе с `PathBase`, статус, длительность, адрес клиента, User-Agent и учётка.
- [ ] Учётки нет — поле учётки пустое. Чтение учётки не отвечает 401.
- [ ] Присланный `X-Correlation-ID` виден в `CorrId` файла. Без заголовка новое значение не появляется.
- [ ] Тело ответа вызывающему — `healthy` (`text/plain`).
- [ ] `GetLevel_HealthCheck_IsVerbose` проходит.

### Заметки

Сейчас обработчик всегда отвечает 200, поэтому строка Information появится вместе с другим статусом обработчика.

Анонимный доступ IIS выключен. Вызов без Windows-учётки IIS отклоняет до приложения: строки обработчика нет. Ответы IIS 401 и 503 в `C:/logs/v2` не пишутся. В файле это та же пауза, что и при остановленном процессе.

Поднятие порога журнала до Information убирает успешные вызовы из `C:/logs/v2`. Статистика и признак паузы пропадают вместе с ними.

Локальный профиль IIS Express в `BlazorSvt/Properties/launchSettings.json` включает анонимный доступ и выключает Windows-аутентификацию. Отказ IIS на стенде этот профиль не показывает.

Пробел: имя учётки и User-Agent системы мониторинга не заданы. В строку попадает то, что пришло с вызовом.

Допущение для проверки на стенде: чтение схемы IIS из обработчика при `ShortCircuit` возвращает имя, которое IIS уже установил, и не превращает `/hc` в 401.
