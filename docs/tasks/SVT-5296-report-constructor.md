## Задача: read-only справочник ReportConstructor (Конструктор отчётов ставок)

### Контекст

**СВТ 2.0** — переписывание MDM тарифов/маршрутов с легаси на **Blazor Server + MS SQL**. Эта задача переносит справочник **только для чтения** (грид, карточка, Excel, API). Редактор в реестре нужен, но в эту задачу не входит (backlog 9.2.16). Загрузчика в реестре нет. Отчёт Excel из архива ставок и средневзвешенных ставок — backlog **5.1.5**, не эта задача.

Источник истины по составу: `.cursor\skills\svt-architecture\catalogs-scope.md`.  
Чеклист: `.cursor\skills\svt-architecture\backlog.md` → пункт **3.3.15**.

### Что сделать

Перенести сущность реестра **ReportConstructor** (EntityInfo **2149**, «Конструктор отчётов ставок») как read-only модуль. На экране — записи-фильтры этого справочника (район, продукт и другие атрибуты, которые оставит discovery). Плоская выгрузка архива ставок, дашборд и универсальный конструктор в задачу не входят.

Имя модуля — `ReportConstructor`: в имени реестра нет `_`. `{LegacyName}` — имя основного примитива из `EntityStructure`; его не подставлять именем реестра, пока шаг 0 не подтвердит, что они совпадают.

Из реестра, без discovery:

- домен **Ставки** (`CatalogDomain.Rates`), меню ЕО = да (`VisibleToEditor: true`), маршрут `/reportconstructor`
- сложность Средняя, пр. RO = 3
- комментарий реестра: запись = список фильтров. Состава колонок в нём нет
- в класс «стабильный словарь с enum» в skill не входит. Отдельного enum ReportConstructor в коде нет. Enum этого справочника, найденный при discovery, не перегенерировать: остановиться по правилу skill

- грид + карточка + выгрузка Excel строк этого справочника
- пункт меню домена **Ставки**
- watermark-sync (снимок, SyncJob, RowVer, SyncState). Каркас — `Modules/TransportRate` и `SqlScripts/Modules/TransportRate`: Structure, Programmability, SyncJob, модуль. Узлы, продукт, срок действия и WHERE членства TransportRate не переносить. Чужой справочник в Sources — только если проекция ReportConstructor его читает. Стабильные словари (RateType, TransportKind, Currency и остальные из таблицы skill) в каскад не входят, даже если проекция читает их Id. RowVer на основную таблицу — по skill, если его там ещё нет
- API: `AddCatalogApi`, код `report-constructors` (обычное множественное число skill), домен `Rates`, ключ `HeaderMenu.ReportConstructor`. `CatalogPeriod` передавать только если в list-DTO есть две даты `DateOnly`

Отдельного согласованного списка колонок нет, в постановку его не додумывать. Короткий список и порядок грида — discovery §1 после фильтра §3. Порядок карточки — §4 после того же фильтра. Атрибут с нулём заполненных неархивных значений в грид и карточку не входит. Дочерний примитив в модуль не входит, пока его явно не включат. Подписи — Dictionary и `grid-column-glossary.md`. Стоп и согласование по skill: пустой заголовок справочника, английский ярлык совпал с системным именем и его нет в глоссарии, неизвестное короткое имя колонки, ссылка без однозначного FK. Согласованное исключение из этого фильтра дописать в комментарий строки `ReportConstructor` в `catalogs-scope.md`. Колонку RO там не отмечать: `[x]` ставится, когда справочник на проде.

### Как делать

1. Skill `.cursor\skills\add-reference-book\SKILL.md` целиком.
2. Строка `ReportConstructor` в `catalogs-scope.md` — домен, меню, приоритет.
3. Эталон каркаса — `Modules/TransportRate` и `SqlScripts/Modules/TransportRate`. Разовый снимок RateType/Currency не копировать. Если discovery найдёт существующий enum этого справочника, остановиться по правилу skill.
4. Релизная копия — `Migrations/2.3.49/` (текущий `VersionPrefix`, папка ещё не закрыта). `2.3.48` не менять. Дельта — следующий свободный номер после уже лежащих файлов. Contractor занимает `001`–`007`, `008` — снимок `All_Programmability.sql`. SVT-5291 и постановки, которые попадут в папку раньше, забирают номера до этой задачи; `009` заранее не занимать. Снимок programmability пересобрать из SoT и оставить последним файлом: прежний снимок в середине не остаётся. В `C:\publish` само по себе не копировать.
5. C# только после наката и проверки SQL на `localhost` / `mdm`.
6. Unit contract-тест DTO и SyncJob; integration smoke грида, карточки и FTS по текстовым полям, которые discovery оставила в гриде; снимок OpenAPI обновить по skill.
