# Реестр справочников СВТ 2.0

## Назначение

Провести ревизию справочников в СВТ 1.0, определить скоуп и приоритеты, чтобы не переносить неиспользуемый функционал в СВТ 2.0.

| Вопрос | Результат | Комментарий |
|---|---|---|
| Решить, какие справочники нужны | Выполнено | Требуется ревью с бизнесом |
| Приоритет | Выполнено | Требуется ревью с бизнесом |
| Структура | Выполнено | Требуется ревью с бизнесом|

## Как читать

| Колонка | Смысл |
|---|---|
| ID | Идентификатор справочника; ссылка на **прод** `https://s001as-svt.sibur.local/masterdata/{id}` |
| RO (только для чтения) / E (редактор) / L (загрузчик) | Необходимость работ: `[x]` или `[ ]` — да, `—` — нет. **RO** отмечен (`[x]`), если read-only уже на проде; иначе `[ ]`. **E** и **L** пока не отмечаем (работы необходимы → `[ ]`, иначе `—`) |
| Пр. RO / Пр. E / Пр. L | Приоритет внутри домена (`1` раньше `2` раньше `3`). Если работы не нужны — `-`. Для E/L, где контур есть, скопирован Пр. RO |
| Меню ЕО | Если `да` — пункт меню виден под ролью «Единое Окно», иначе виден только «Админу». Сейчас ЕО — редактор всех доменов. После упразднения ЕО (MVP 0.4) то же «да» = пункт меню **редактора этого домена**; `нет` = только «Админ» |

## Исключения

Пилот фреймворка записи (TransportLegs, MVP 0.5/0.6) **не** равен первому Gate C (домен Ставки).

Схлопывание Вид транспорта + Тип транспорта + Тип 3 ур. — отдельная задача **после полной миграции (MVP 2.0 / Gate D)**; до этого переносим три справочника as-is.

## Меню

Меню верхнего уровня имеет короткие подписи (требование к backlog 0.2.2.4). При наведении — подсказка с полным именем домена:

| Пункт меню | Подсказка |
|---|---|
| Ставки | Ставки |
| Маршруты | Маршруты |
| Продукты | Продукты |
| Склады | Склады и ограничения |
| МК | Матрица каналов |
| ЦБД | Интеграция с ЦБД |
| Вспомогательные | Вспомогательные справочники |

Роль «Единое Окно» (после MVP 0.4 — редактор домена) видит только справочники с **меню ЕО = да**. С **меню ЕО = нет** — только **Админ**, в том же домене (отдельного админ-дерева нет).

Пункты внутри домена в шапке идут по алфавиту подписи на текущем языке интерфейса. Колонка «Пр. RO» задаёт приоритет работ, не порядок меню. Шапка собирает пункты из вкладов модулей (`AddCatalogMenu`; домен — `CatalogDomain`: `Rates`, `Routes`, `Products`, `Warehouses`, `MK`, `Cbd`, `Other`). Домен без вкладов не показывается. До MVP 0.4 флаг «меню ЕО» хранится в регистрации и меню по роли не фильтрует.

Колонка «Имя» — имя сущности легаси (`PrimitiveEntityInfo`). Модуль в коде может называться иначе: `Rates` → `TransportRate` (ключ `TransportRateId`), `TransportLegs` → `TransportLeg` (ключ `TransportLegId`).
